## 一、结论

# 两者都不及格。

一句话理由：**这一轮根本没有测到威胁模型。** 权重第二高的"失败可归因"（1.30）经算术核对被证明是"被 Listener 杀死的比例"的同义词，携带零独立信息；权重最高的"技巧表达度"（1.35）在两方都撞上了公式的双端饱和点，读数 0.350 的真实含义是"此处无分辨率"。剔掉这两项污染之后，甲乙的差距从 0.1208 塌缩到 0.0223 —— 而在这个噪声量级里，两个方案在玩家体验上其实是**同一个东西**：一个由"你有没有按下全功率声呐"这一个比特触发的开关，区别只是甲对这一下几乎不惩罚（listener 死因 9.3%），乙对这一下判死刑（listener 死因 73.9%）。

甲的**立论**应当直接作废，不要调参。乙的**立论**是对的，但它的**实现**在代码注释里亲口承诺要避免的那件事上翻了车，当前形态同样不可发布。

## 二、决定性证据

### 证据 1（最重要）：「失败可归因」是死因表的一列的别名，不是一个独立指标

用报告自己的数字做算术：

| | 死亡局占比 | listener 死因占比 | listener 死亡数（按 2700 局折算） | 报告的可归因分 | 可归因死亡数 |
|---|---|---|---|---|---|
| 甲 | 40.4% ≈ 1091 | 9.3% | **≈ 101** | 0.093 | **≈ 101** |
| 乙 | 52.3% ≈ 1412 | 73.9% | **≈ 1043** | 0.740 | **≈ 1045** |

两行都对得上到个位数。也就是说：

> **可归因分数 ≡ 被 Listener 杀死的死亡占比。** 其余三种死因对这个指标的贡献约等于 0。

这不是巧合，是实验台的硬约束。查 `model.ts` 与 `variants.ts`：

- `lost`（超时）：`hadIdentifiableMistake` 只在 `trace.cause === 'asphyxiation'` 时才可能为真，所以 **`lost` 恒为不可归因**。
- `asphyxiation`：判据是 `wastedBreathsDetected`，要求**声呐行动占决策数 > 28%**。而两方的实测感知占比是 3.0% 和 12.6% —— **这个阈值在本轮实验里不可能被触及，等价于恒假**。
- `trauma`：要求 `believed >= 0 && actual - believed > 0.3`，即"感知过、但读数严重失真"。在甲的 3% 感知率下几乎无从触发（甲 trauma 占 7.5% 的死亡，却对可归因贡献 ≈ 0）。
- `listener`：这里出现了本轮最严重的实验污染 ——

```
// thresholdThreat（model.ts:161）
return { killed: true, warned: true, attributable: p.noise > 18, pressure: 1 };

// gradientThreat（model.ts:228）
// presence 一路可读，所以走到这一步的死亡**总是**可归因
return { killed: true, warned: true, attributable: true, pressure: 1 };
```

**一个模型把可归因性从状态里推导出来，另一个模型把它写成字面量 `true`。** 后者不是测量结果，是设计者的自我断言被塞进了被测对象里。第二高权重的指标，被测对象自己给自己打分。

这条证据的量化后果：把 attributability（权重 1.30）整列移除后重算加权总分 ——

| | 原始总分 | 剔除 attributability 后 |
|---|---|---|
| 甲 | 0.4216 | 0.4831 |
| 乙 | 0.5424 | 0.5054 |
| 差距 | **0.1208** | **0.0223** |

**乙 全部优势的 81.5% 来自那一行硬编码。** 剩下的 0.0223 落在两个方案各自 2700 局的抽样噪声量级里，不足以支撑任何选型决策。

### 证据 2：两个方案都不是"渐进"的，都是同一个开关

把噪音数值代进去算：

- **触发点相同。** 全功率 boom 加 28 噪音；世界反应扣掉 `0.8 × 7 = 5.6`，威胁 tick 看到的是 `noise ≈ 22.4`。甲的召唤阈值是 `p.noise > 22` —— **一次 boom，刚好过线**。
- **甲：过线后轻判。** 追击者被放到 `farthestFrom`（图的最远端），awareness 0.4，每回合只走 `floor(spent/4)` 步（移动时 spent=2 → **0 步**）。所以它多数回合根本不动。结果：listener 只占 9.3% 的死亡。
- **乙：过线后死刑。** `presence += 22.4 × 0.0042 × 7 − 0.0065 × 7 = +0.613`。之后噪音以 0.8/呼吸 衰减，需要 35 个呼吸才排空，而这 35 个呼吸里 presence 还在继续被喂养，两三回合内就撞到 1.0，`wantDist = 0`，强制接触，低技巧 50% 当场死亡。结果：listener 占 73.9% 的死亡，全局平均存活只有 127 呼吸。

所以两个模型都是**同一个一比特函数**：`f(你有没有 boom 过)`。乙 宣称的"一根始终在收紧的绳子"在数值上不成立 —— 喂养系数 `0.0042 × noise × spent` 与偿还系数 `0.0065 × spent` 差了两个数量级（boom 后瞬时喂养是偿还的 94 倍），presence 不是绳子，是**跳闸**。行动表印证了这一点：乙 的 `sonar:boom` 只有 1.91%，而 listener 死因 73.9% —— 一局里那不到两次的 boom，就是那 73.9%。

**结论：这一轮实验里被比较的不是"阈值召唤 vs 连续逼近"，而是"同一个阈值召唤的两档惩罚力度"。** 设计问题没有被回答。

### 证据 3：乙 的三个"优势"是同一个退化行为被数了三遍

乙 的 `sonar:passive` 占全部行动 10.13%，占感知行动 80.6%。检查 `sonar.ts` 的 passive 参数：`breaths 2, noise 0, radius 1, fidelity 0.35`。**噪音为 0**，因此在 `senseUtility` 里 `noiseRisk = o.noise × ... = 0` 恒成立 —— 无论威胁读数多高，passive 都不承担任何风险。在一个"噪音会杀死你"的威胁模型下，唯一零噪音的按钮当然会被刷屏。

于是：

| 报告里呈现为 | 实际是 |
|---|---|
| 感知行动占比 12.6%（甲只有 3.0%，报告判为"健康"） | 免费按钮的刷屏量 |
| 决策熵 0.665（比甲高 0.174，报告标注"显著"） | 同一批 passive 把熵抬起来了 |
| 感知档位内部最高频 80.6%（报告判为"存在统治性档位"） | 同一件事，这次被正确地判为缺陷 |

**三个数字，一个行为。** 报告把它算作两个优点、一个缺点。修正后应当算作**一个严重缺陷**：乙 并没有让声呐运转起来，它只是让声呐的**无取舍档位**运转起来了。真正体现"风险—信息三角"（GDD §4.4）的 chirp 与 boom，在乙 里合计只有 2.44%，比甲 的 2.07% 高不了多少。

## 三、反方论据（对两方各自最强的辩护，以及它们为什么仍然不够）

**为乙 辩护：**
1. `learnability = 1.000` 是**真实的**——它基于 duration，没有被硬编码污染。方向性信号成立：威胁可读时，玩家表现确实随技巧单调改善。
2. "被过度使用的动作"比"没人用的机制"好修。给 passive 加代价是一行参数；给一个 3% 使用率的机制找存在理由是重做。
3. 它的立论与 Into the Breach 的先例一致（见 §四.6），方向是对的。

**为甲 辩护：**
1. `意外率 1.000` 与 `决策密度 1.000` 是真的满分，没有污染。
2. **感知档位有效多样性 2.65 vs 乙 的 1.81** —— 在"三档之间是否存在真取舍"这个问题上，甲 是**唯一一个证明了取舍存在**的方案。甲 的三档分布 54.3% / 31.0% / 14.7% 接近健康形态；乙 是 80.6% / 15.2% / 4.2%。
3. 甲 的平均存活 259 呼吸更接近 GDD §3 声称的轮回节奏；乙 的 127 呼吸把一个靠 Stigma 累积与叙事分支支撑的 roguelite 的单轮长度砍掉一半以上，对元进度结构是结构性伤害。

**为什么都不够：** 甲 的第 2 条反而加重了对它的判决 —— 它证明了取舍**存在**，然后让玩家**一局只做两次**这个取舍（3.0% 感知率 ≈ 每局 2 次声呐）。乙 的第 1、3 条都指向"立论对、实现错"，而实现错到它的核心承诺（可读性）在指标上直接归零。没有一方处在"调参即可发布"的状态。

## 四、逐条判读四个异常

### 4.1 可归因 0.09 vs 0.74 —— 对 roguelite 意味着什么

**先说这个数字本身不可信**（证据 1）。但把它背后的**真实**情况说清楚，比这两个数字重要得多。

GDD 支柱 **P6：死亡是叙事，不是惩罚 —— 保留"知识"，世界重组**。元进度的货币是知识。知识只能从"我看懂了自己怎么死的"里提取。因此在本作里，**可归因性不是八个指标之一，它是元进度系统的输入带宽**。

按这个标准看甲：91% 的死亡不可归因，意味着**每 11 局里有 10 局，复苏仪式把玩家捞回来，而他两手空空**。轮回不再是学习，是重掷骰子。这直接判甲死刑 —— 不是因为分数低，是因为它和 P6 在结构上不兼容。GDD §1 写着"任何提交的机制，如果不能明确指出它服务于上述哪一条支柱，就删掉"：甲 不只是没服务 P6，它**否定**了 P6。

再看乙 的 0.740。它的真实含义不是"玩家能复盘"，而是"**乙 更常用怪物杀你**"。这两件事在本轮实验台里被混为一谈。而且 §4.2 会证明，乙 的"可读性"在玩家侧其实已经失效 —— 所以那 0.740 不仅是别名，它测的还是**一个不成立的前提**。

更麻烦的一层：甲 的主要死因是 asphyxiation（69.3%）+ lost（13.9%）= 83.2%，而实验台把这两种死因**定义**为不可归因。这意味着"提升可归因性"在当前实验台上只有一条路径——**让玩家更多地死于怪物**。任何优化器跑在这个指标上，都会收敛到"把怪物做得更致命"。乙 就是这条路径的终点。**这是一个会把设计带向错误方向的指标，必须在下一轮之前修掉（见改进提案 P2）。**

### 4.2 意外率 0 —— 是"太少"还是"太多"？

**判定：太多。乙 的威胁预警率 ≥ 10 次 / 100 呼吸，已经退化为背景噪音。**

推导（`computeSurprise`：`rate < 1.5` 时得分 `rate/1.5`，`rate > 4` 时得分 `1 − (rate−4)/6`，在 `rate ≥ 10` 归零）。得分恰好 0.000 只有两种可能：`rate ≈ 0` 或 `rate ≥ 10`。排除前者：

- `trace.surprises` 有两类来源——**移动侧**（信念错判、盲走进高危房、灾害触发）与**威胁侧**（`tick.warned`）。
- 移动侧机制在两个变体里**完全相同**（`runTrial` 里的共享代码），且甲 的总意外率落在 [1.5, 4]，说明移动侧的基线**显著大于 0**。
- 意外率是"每 100 呼吸"的**密度**，不受局长短影响。乙 的盲走比例（0.55% + 0.17%）还高于甲（0.07% + 0.04%），灾害掷骰完全一致。

所以乙 的移动侧基线不可能低于甲，`rate ≈ 0` 在结构上不可能。**只剩 `rate ≥ 10`。**

成因定位到一行代码 —— 而且正是作者在注释里声称要避免的那件事：

```
// 只有"它更近了"才值得报警。每次档位变动都响会把预警变成背景噪音，
// 玩家很快就学会无视它 —— 那样可读性就名存实亡了。
const warned = Math.floor(presence * 7) > Math.floor(prev * 7);
```

**注释是对的，实现没做到。** `floor(presence×7) > floor(prev×7)` 只比较**相邻两回合**，没有对"本局达到过的最高档"上锁（没有滞回 / hysteresis）。presence 每回合的增量是 `noise × 0.0042 × spent − 0.0065 × spent`，噪音一有残余就在正负之间摆动，于是 presence 在任意一个档位边界（1/7 = 0.1429 的整数倍）附近来回穿越，**每一次向上重穿都再响一次**。叠加第二个无节制的来源：`hops == 0` 时无条件 `warned: true`，它贴在你身上的每一个回合都在报警。

**严重程度：这是乙 的否决项，比可归因造假更致命。** 乙 的全部论证只有一句话——"距离始终对玩家可读"。一个每两三个呼吸就响一次的读数，人类玩家在第三局就会把它当作环境音过滤掉。**可读性被自己的报警频率吃掉了。** 而一旦读数在玩家侧失效，`attributable: true` 那行硬编码就从"污染"升级为"与事实相反"：玩家看着一个他已经学会忽略的仪表死去，然后实验台记录"这次死亡完全可归因"。

对照 Alien: Isolation 的动作追踪器：它之所以几十小时不失效，是因为**它不主动报警**。它只在玩家**主动举起它**（付出视野与机动性代价）时才给读数。预警的稀缺性是玩家自己买的。乙 把读数做成了免费推送。

### 4.3 声呐 3% —— 招牌机制被架空，有多致命

**致命，但责任要分摊：约三分之一在威胁模型，三分之二在实验台的共享缺陷。**

根因不是"甲 让声呐不值得用"，而是**一次全功率 boom 就把整张地图解决了，之后声呐永远没有第二次用武之地**：

1. `buildWorld` 的脊柱允许 `parent = rng.int(i-4, i-1)`，即单跳最多跨 4 个编号，再加 `size × 0.3 = 12` 条弦。40 个房间的图直径很小 —— **radius 7 的 boom 基本覆盖全船**。
2. `senseUtility` 的信息价值是 `min(unknownNearby, radius × 2.1) × fidelity`，而 `unknownNearby` 只统计 **3 跳内**的未知房间（`countUnknownWithin(p, w, 3)`）。**boom 的揭示半径（7）永远大于效用函数的观察半径（3）**，所以 boom 一响，`unknownNearby` 立刻归零，声呐的效用从此恒为负。**boom 亲手把自己的后续价值清零了。**
3. `reveal` 写进的 `belief` **永不过期**。这与 GDD 支柱 **P4「地图是活的」** 正面冲突：文档说拓扑会在玩家不观察时重连，实验台里却是一次扫描、终身有效。

所以 3.0% ≈ 每局两次声呐，其中第一次就解决了游戏。**招牌机制退化成一个开局按一次的解谜按钮。**

威胁模型在这里的责任：`senseUtility` 的噪音代价系数读的是 `ctx.threatReadout`（来自 `threat.readable`）。甲 的 `readable` 在未召唤时返回 −1、召唤后除非 ≤2 跳也返回 −1 —— 也就是**绝大多数时间返回"无从判断"**，`max(0, −1) = 0`，噪音风险系数塌到 0.062 的地板。**在甲 之下，声呐几乎不承担噪音风险**，可它依然只有 3% 使用率。这反过来证明：甲 的问题不是"声呐太危险所以没人用"，而是"声呐太快就没东西可看了"。

而乙 的 12.6% 不是修复，是另一种病（证据 3）：真正有取舍的两档合计 2.44%，与甲 的 2.07% 在同一水平。**两个方案都没有让风险—信息三角运转起来。**

致命程度评级：**最高**。GDD §0 把声呐写成"你唯一的感知手段"，§2.2 写"坐标即玩法"。一个让唯一感知手段变成开局一次性消耗品的系统组合，不是平衡问题，是这款游戏不存在了。任何一个候选威胁模型，如果不能把感知率推到 12% 以上**且**让三档都保持在 20%–45% 的区间，都不应当进入下一轮。

### 4.4 乙 的 80.6% 统治性档位 + 73.9% 单一死因

这两个数字是同一个因果链的两端，必须合起来读：

> **boom 是自杀（§证据 2）→ 玩家只按 passive（80.6%）→ 唯一被使用的感知档位是零噪音的那一档。**
> **偶尔还是有人 boom（1.91%）→ 那 1.91% 几乎全部转化为死亡（73.9%）。**

乙 架空声呐的方式比甲 更隐蔽也更糟：甲 让声呐**无用**，乙 让声呐**有害**。在一款以"按下按钮，世界以回波的形式在你脑中画出一张图"为电梯陈述的游戏里，把那个按钮做成自杀键，是对核心幻想的直接否定。

73.9% 单一死因同时说明**威胁维度只剩一个**。GDD §4.5 设计了 STALK / CONTACT / PANIC 三相遭遇、部位定向攻防、认知系统——乙 的数值让这一整套内容永远来不及展开：presence 从 0.613 撞到 1.0 只需要两三个回合，玩家没有 GDD §4.3 承诺的"8–20 个呼吸的窗口逃离或隐藏"。**乙 违反了 GDD §4.3 白纸黑字的规格。**

顺带：甲 的死因分布（69.3 / 13.9 / 9.3 / 7.5）表面上更健康，但它的头名是 asphyxiation ——"我氧气用完了"。**这不是恐怖游戏的死因，是资源管理游戏的死因。** 船外那个靠听觉捕猎的东西，在甲 的世界里只造成了 9.3% 的死亡，它在机制上几乎不存在。两个方案，一个让怪物消失，一个让怪物成为唯一。

### 4.5 技巧表达度完全相等（0.350）—— 是模型缺陷。三重缺陷。

**这不是巧合，也不是"两个方案一样好"。0.350 是这个公式的一个特定饱和点的读数。**

```
rateGap = Math.max(0, hiRate - loRate)
durGap  = Math.max(0, (hiDur - loDur) / loDur)
return Math.min(1, (rateGap / 0.45) * 0.65 + Math.min(1, durGap / 0.9) * 0.35)
```

时长项的上限恰好是 **0.35**。`0.350 = 0 + 0.35 × 1` 是唯一自然的分解：

> **`rateGap` 被 `Math.max(0, ·)` 压到了 0，`durGap` 被 `Math.min(1, ·)` 顶到了 1。**

（另一种凑法需要 `rateGap = 0.2423` 且 `durGap ≤ 0`，并且两个不同的模型在 2700 局上把这个值同时命中到小数点后三位——可以排除。）

而这个分解有一个独立的交叉验证：**乙 的 `learnability = 1.000`**。learnability 用的是 `(hiDur − midDur)/midDur ≥ 0.55`，说明乙 的**存活时长强烈随技巧上升**；而 skillExpression 的存活率项为 0，说明乙 的**存活率不随技巧上升**。两个指标跑在同一批轨迹上，给出的是一个自洽的、且极其难看的结论：

> **技巧买到的是"死得慢"，不是"逃出去"。**

这正是报告 §三 判读要点第 4 条自己定义的致命项——"存活率在不同技巧档位之间没有差别是致命的"。**两个方案都踩中了它，而 0.350 这个数字恰好把这条信息压缩掉了。**

三重缺陷，按严重性排序：

**缺陷一 · 双端饱和碰撞。** 一端触底、一端触顶时，公式退化为常数 0.35，对"两个方案在饱和区内部差多少"完全失明。修法：存活率项改为有符号上报；时长项的归一化分母从 0.9 提到 2.5（本轮实测显然 ≥ 0.9，饱和说明标尺太短）。

**缺陷二 · 单向截断掩盖负相关。** `Math.max(0, hiRate − loRate)` 让"技巧无关"和"**技巧有害**"得到同一个分数。而有理由怀疑本轮至少一方是**负的**：`moveUtility` 里未知房间的风险惩罚是 `risk × (0.5 + skill × 1.7)`，未知房间 `risk` 固定 0.58，而进入未知房间的收益 `progress` 固定 0.42。技巧 1.0 时净值 = `0.42 − 0.58 × 2.2 + 0.35 = −0.51`，**高技巧玩家在数学上被禁止走进黑暗**。行动表印证：盲走合计 0.11%（甲）/ 0.72%（乙）。而出口在 `size − 1`，只能穿过未知区抵达。于是高技巧玩家在已知安全区打转到超时——甲 的 `lost` 13.9% 就是这批人。**技巧越高越不敢去出口，这是负相关，却被截断成 0。**

**缺陷三 · 九档数据只用了两个三分位。** 跑了 9 个技巧档位（`SKILL_BINS = 9`），`computeSkillExpression` 只取首尾各 3 档合并，中间形状（是否单调、拐点在哪、是否存在"中等技巧陷阱"）全部丢弃。而 skillExpression 用 lo→hi、learnability 用 mid→hi，两个指标切同一批数据的不同片段却互相矛盾，这个矛盾本该直接报出来。

**结论：技巧表达度这一项本轮无效，不能用于选型。** 在修好之前，不要相信任何关于"哪个威胁模型更奖励技巧"的判断。

### 4.6 张力曲线 0.26–0.28 —— 对恐怖节奏意味着什么

报告的提示说"低分通常意味着一路高压或一路平淡"。**本轮是第三种情况，而且比那两种都糟：一路中压。**

拆 `tension[i] = clamp01(fear/100 × 0.42 + (1 − oxyFrac) × 0.30 + pressure × 0.28)`：

1. **主成分是一条永不回落的单调斜坡。** `(1 − oxyFrac) × 0.30` 随氧气消耗单调上升，唯一的下降来源是氧气缓存（只有 34% 的房间有，且都在高危区）。恐怖节奏的对比度来自**退潮**，而这个模型里没有退潮。
2. **威胁对张力几乎没有贡献。** 甲 的 `pressure = 0.18 × awareness + 0.1`，值域 [0.1, 0.28]，乘 0.28 后对张力的贡献是 **[0.028, 0.078]** —— 一个宽度不到 0.05 的常数带。**船外那个东西在张力曲线上是一条直线。** 乙 的 `pressure = presence`，但 presence 是跳闸（§证据 2），贡献的是一个阶跃而非起伏。
3. **唯一的高频分量是恐惧，而恐惧的抖动来自房间危险度的随机掷骰**（`fear + actual × 14 − 1`，每回合再 `−0.25 × spent`），不来自威胁。所以曲线上的"起伏"是**噪声**，不是**节奏**——这会同时压低 `flipScore`（反转次数偏离 `length/12` 的理想值）和 `varScore`（方差达不到 0.045）。
4. **两端都够不着。** 满张力需要 `fear = 100` **且** `oxyFrac = 0` **且** `pressure = 1` 同时成立；最低点被恐惧地板与氧气斜坡托住。实际曲线被压在中间三分之一（实测方差 0.012–0.03，满分线 0.045，**幅度只有目标的三到六成**）。

设计含义：**玩家既没有安静的时刻，也没有尖叫的时刻。** 恐怖的经济学是"用长时间的低成本安静，换一个瞬间的高成本尖叫"——SOMA 的走廊、Isolation 的储物柜、《铁肺》的黑屏都在做同一件事。一条恒在 0.3–0.4 之间小幅抖动的曲线，训练出的是**疲劳**而不是恐惧：玩家的生理唤醒水平在 20 分钟内完成适应，此后任何事件都读不出来。

0.26 vs 0.28 的差值（0.025）远小于本轮其他指标的噪声，**不构成选型依据**。真正的结论是：张力曲线的失败是**两方共有的、且成因不在威胁模型**（主成分是氧气斜坡），必须在实验台层面修（提案 P5）。

### 4.7 Into the Breach 先例如何改变判断

Into the Breach 把敌方意图 **100% 提前一回合公开**，结果不是紧张感下降，而是游戏变成纯粹的决策艺术。它证伪的命题恰好是甲 的立论：

> 甲 的论点（见 `threat.ts`）："在那之前玩家得不到任何余量反馈 —— 安静与死亡之间是二值跳变。"

**这个赌注已经被先例判负，并且被本轮数据再判一次负**（可归因 0.093，与 P6 结构性冲突）。**甲 的立论应当从候选集里永久删除，不是调参。**

但 Into the Breach 同时也给乙 判了半负，而这一点报告里没人提：

> **可读 ≠ 可预测。**

Into the Breach 显示的不是"威胁等级 0.63"，而是"**下回合这只虫子打这一格**"——一个**有位置的、绑定的、可被规划反制的承诺**。乙 的 presence 是一个标量情绪计：它告诉你**该有多害怕**，不告诉你**该做什么**。一个只能被感受、不能被规划的读数，产生的是焦虑，不是决策。这就是为什么乙 拿到了 0.665 的决策熵却仍然只是在按免费按钮——**读数没有转化成可执行的选项**。

这条先例直接决定了第三方案的形态：**威胁必须把它的下一步写在地图上，而不是写在仪表盘上。**

## 五、改进提案（5 条，每条注明指标从多少到多少）

> P1–P2 是**下一轮实验的前置条件**：不先修，下一轮的数据同样不可用。

### P1 · 给 presence 加滞回，把接触预警合并为事件
**指标：意外率 0.000 → 1.000（纯威胁预警率从 ≥10 次/100 呼吸 压到 2–4 次/100 呼吸）**

- 在 `threatState` 里增加 `peakBand`。`warned` 改为 `band > peakBand` 的单调闩锁；`peakBand` 只有在 presence 跌破 `(peakBand − 1)/7 − 0.08` 时才允许回落（双阈值滞回，0.08 的回差覆盖单回合最大抖动 0.013×6）。七档全部刷新一次 = **每局上限 7 次**。
- `hops == 0` 的接触预警加 **12 呼吸冷却**，同一次接触序列只报一次。
- 以乙 当前 127 呼吸的局长计算：7 次升档 + ≈2 次接触 ≈ **7.1 次/100 呼吸**；配合 P5 把局长恢复到 200+ 呼吸后落到 **≈4.5**，再扣掉移动侧基线的重叠即进入 [1.5, 4]。

### P2 · 拆掉可归因性的硬编码，两个模型换同一把尺
**指标：让 0.093 / 0.740 重新携带信息。预期真值 甲 ≈ 0.15–0.25、乙 ≈ 0.35–0.50（乙 会掉，因为"一路可读"在缺滞回时是假的）**

- 从 `ThreatTick` 里**删除 `attributable` 字段**。可归因性不许由被测对象自报，改由 `runTrial` 在模型外统一判定：
  `attributable = (死亡前 20 呼吸内，threat.readable() 曾 ≥ 0.5) && (期间玩家至少选过一次不减少 hops(hunter, p.at) 的行动)` —— 即"警报响过，而你没有远离"。
- 修掉另外三条死因的恒假判据：`lost` 的判据改为"最后 60 呼吸内 `distToExit` 没有减少"（原地打转是可复盘的错误）；`asphyxiation` 的 28% 声呐阈值改为"氧气跌破 30% 后仍执行过 ≥2 次高噪音行动或 rest"；`trauma` 保留但把阈值从 0.3 放宽到 0.2。
- **这条不提分，它的价值是让后续每一个决策不再建立在污染数据上。** 不做这条，下一轮仍然只是在测"谁更常用怪物杀人"。

### P3 · 让信息会过期，把声呐从一次性解谜变成持续心跳
**指标：感知占比 3.0% → 15–20%；感知档位内部最高频 80.6% → 40–45%；有效多样性 1.81 / 2.65 → ≥ 2.7**

三处，缺一不可：

- **(a) belief 加时间戳并衰减。** 每条 belief 记录写入时刻，每过 **25 呼吸**置信度 −0.1，跌破 0.25 时该房间退回 `-1`。这不是补丁，这是 GDD **P4「地图是活的」** 本来就承诺的东西——舱段重连后，旧回波就是过期情报。
- **(b) 把 `countUnknownWithin` 的半径从 3 提到 7**，与最大声呐半径对齐。当前 boom 揭示 7 跳、效用函数只看 3 跳，boom 自己把自己的后续价值清零了——**这一处单独就是 3% 使用率的最大单一成因**。
- **(c) 给 passive 一个真实代价。** 现在它 `noise: 0` 因而在任何威胁模型下都是严格占优的免费动作（80.6% 的唯一成因）。改为"贴舱壁聆听：零噪音，但必须静止 2 呼吸，期间威胁的逼近判定照常推进，且**期间无法响应任何预警**"。零噪音换零机动性——这才是取舍。

### P4 · 让技巧买到逃生率，而不是买到死得慢
**指标：技巧表达度 0.350（饱和无效值）→ 0.60–0.70，且存活率项首次 > 0（预期高低技巧存活率差 +0.25 以上）**

- **机制侧：** 未知房间的 `progress` 从固定 `0.42` 改为随"当前已知区域的剩余价值"反向上升——已知区被榨干时，走进黑暗的价值必须超过留在原地。同时把未知房间风险惩罚里的技巧放大 `risk × (0.5 + skill × 1.7)` 改为对**已感知**房间才放大；对未知房间用固定系数。当前公式让技巧 1.0 的玩家进入未知区的净效用为 −0.51，**数学上禁止高技巧玩家去出口**。
- **指标侧：** `Math.max(0, hiRate − loRate)` 改为有符号上报（负值必须能被看见）；时长项归一化分母 0.9 → 2.5 解除饱和；报告输出 **9 档的存活率与时长序列**，而不是两个三分位标量。

### P5 · 给张力曲线造出退潮
**指标：张力曲线 0.259 / 0.284 → 0.55+（方差 0.012–0.03 → ≥ 0.045，反转次数向 length/12 收敛）**

- **(a) 拆掉单调斜坡。** `(1 − oxyFrac) × 0.30` 永不回落。改为 `(1 − oxyFrac) × 0.30 × f(到最近已知氧气缓存的跳数)`，`f` 从 0.35（站在补给点旁）到 1.0（6 跳外）。**知道补给在哪，本身就应该让人喘一口气**——这同时给了声呐第三个存在理由。
- **(b) 让威胁主导张力。** 甲 的 pressure 值域 [0.1, 0.28] 是条直线。改为直接绑定跳数距离：`pressure = clamp01(1 − hops(hunter, player) / 7)`，值域跑满 0–1。威胁应当是张力的主旋律，不是恐惧噪声的陪衬。
- **(c) 强制退潮。** 接触幸存后 **20 呼吸内它必然远离**（当前是 `rng.pick(adj)` 随机游走，可能原地徘徊）。每一次幸存都必须兑现一个可感知的波谷，否则"逃掉了"这件事在体感上不存在。

## 六、第三方案：**「声痕」THE LEDGER —— 承诺式威胁**

> 一句话：**把威胁从"一个标量情绪计"改成"一条公开的、由玩家亲手写下的行动队列"。**
> 它不读你的位置，它读**你留在船上的声音**。

### 6.0 设计原则

三个待解问题有一个共同的根：**当前两个模型都把 Listener 的目标设成"玩家"**。只要目标是玩家本人，玩家就只有"躲"这一个动词，噪音就只有"别发出"这一个正确答案，声呐就必然被架空，死亡就必然只能归因为"我响了"这一句废话。

THE LEDGER 换一个公理：

> **Listener 追逐的不是你，是声音。**

由此，噪音从**惩罚**变成**资源**，声呐从**风险**变成**工具**，死亡从**运气**变成**调度失误**。

### 6.1 核心机制

**M1 · 声痕（Echo Mark）：噪音有位置、有强度、有寿命。**

噪音不再是玩家身上的一个衰减标量 `p.noise`，而是留在**地图节点上**的对象：

| 行为 | 声痕强度 | 留在哪 |
|---|---|---|
| 走路 | 1.2 | 经过的房间 |
| 休息 | 0（而且抹掉当前房间 4 点） | — |
| `sonar:passive` | 0 | — |
| `sonar:chirp` | 9 | 当前房间 |
| `sonar:boom` | 28 | 当前房间 |
| 灾害触发 | 7 | 当前房间 |

声痕按 `−0.8/呼吸` 衰减（沿用 GDD §4.3 的数值），并按 §4.3 已写明的"水中传播"向相邻房间溢出 40%。

**M2 · 它的规则完全公开，且完全确定：它走向当前最强的声痕。**

- 每回合，Listener 朝**全船强度最高的声痕**移动一步（`stepToward`）。
- 抵达后，它**吃掉**那个声痕（归零），然后转向下一个最强的。
- 平局时取离它更近的。**没有随机数。**

这是 Into the Breach 式的完全透明：规则可背诵、下一步可推演，但最优解很难。玩家永远可以在纸上（GDD §2.2「手绘心智地图」）算出它在哪 —— **而算这件事本身就是玩法**。

- 它**不知道你在哪**。如果你站在自己刚留下的声痕上，它来的是声痕，撞上你只是顺带。
- 这同时是 Alien: Isolation 双 AI 的正确实现：规则层（"追最强声痕"）保证它永远在朝某处压来，感知层（"它只认声音"）保证它的下一步局部可读。

**M3 · 声呐的双重用途：同一个按钮，两个相反的意图。**

这是解开"声呐被架空"的钥匙。boom 现在有两种完全不同的打法：

- **当眼睛用**：原地 boom，半径 7、保真 0.98，看清全船——代价是你在**自己脚下**放了一个 28 的声痕，等于把它叫到你现在站的地方。
- **当诱饵用**：boom 之后**立刻离开**。那个 28 的声痕会把它拽向一个**你已经不在的房间**，并且在它走过去、吃掉声痕的这段时间里（跨越大半张图，通常 10–20 回合，正好落在 GDD §4.3 承诺的"8–20 个呼吸的窗口"），全船对你开放。

于是本作最重要的微观决策从**"要不要 boom"**变成**"boom 之后往哪走、走多快"**。每一次使用声呐，都必须配一套撤离计划。

**chirp 在这条链上成为真正的调节旋钮**：强度 9 **盖不过**一个尚未被吃掉的 28 声痕。所以 chirp 的安全性**取决于上一次 boom 的诱饵是否还在生效**——同一个档位，在不同局面下时而免费、时而致命。**这是 80.6% 统治性档位的解药：档位的价值随局面移动，没有可背诵的答案。**

**passive** 按 P3(c) 改造：零噪音、零机动性，用来在诱饵生效的窗口里**低成本地确认它有没有咬钩**。三档由此形成一个闭环：boom 布饵 → passive 确认 → chirp 在窗口内低成本补图。

**M4 · 预警是"它换目标了"，一局最多 5–7 次，每次都携带方位。**

- 报警**只在 Listener 切换目标声痕时**触发，播报的是**方位**（"左舷方向的管道开始震动"），不是危险度数值。
- 切换只发生在两种时刻：**玩家制造了新的、更强的声痕**，或**它吃掉了旧的**。两者都由玩家的噪音决策直接引发。
- 因此 **预警次数 ≤ 玩家的高噪音行动次数 × 2**，被机制本身天然限流，**不需要滞回补丁**。
- 每一次响，玩家都能立刻指着说"是我刚才那一下"。**预警与因果是同一件事。**

**M5 · 配套的第二威胁：水位（威胁链）。**

Listener 惩罚"响"。如果只有它，占优策略就是**永不发声、在已知安全区打转**——那正是本轮高技巧玩家的行为（甲 的 `lost` 13.9%）。所以必须有一个惩罚"慢"的正交威胁：

- **水位随总呼吸数单调上升，完全可预测，完全不理会噪音。** 淹没的房间不可通行，且淹没顺序由船体倾角决定——**可以推理，因此可以规划**。
- 两个威胁正交：一个罚响、一个罚慢，玩家被夹在中间。这才是"双 AI"的真实结构（Isolation 的 Director 负责不让你舒服，Alien 负责局部可读）。
- 它顺手修掉技巧表达度：**拖延有了明确的死线**，高技巧玩家必须把"进未知区"算进来。
- 这也是《死亡搬家》式威胁链的入口：逃离 Listener 的最优路线，会把你交给水位；抢在水位前面，会逼你发声。

### 6.2 为什么它同时解决三个问题

| 问题 | 当前状态 | THE LEDGER 的解法 | 预期指标 |
|---|---|---|---|
| **失败可归因** | 0.093 / 0.740（后者是硬编码） | 每一次死亡都能回溯到**一个具体的声痕**，而声痕是玩家自己放下的、有位置有时间的对象 | **0.75–0.85**（用 P2 的统一尺子测的真值） |
| **预警变噪音** | 乙 = 0.000（≥10 次/100 呼吸） | 预警只在换目标时触发，次数被玩家的噪音决策数天然限流；内容是方位而非数值 | **1.000**（2–4 次/100 呼吸） |
| **声呐被架空** | 3.0% / 12.6%（后者是免费档刷屏） | 声呐既是唯一的眼睛、又是唯一的诱饵；配合 P3(a) 的情报过期，需求持续再生 | **15–20%**，档位内最高频 **40–45%**，有效多样性 **≥ 2.7** |
| 技巧表达度 | 0.350（饱和无效） | 水位死线逼迫进未知区；诱饵调度有明确的优劣解与可推演的最优路径 | **0.65+**，且存活率项首次 > 0 |
| 张力曲线 | 0.259 / 0.284 | "布饵 → 它转向 → 我撤离 → 它吃掉声痕 → 安静"是一个自带波谷的四拍循环 | **0.55+** |
| 单一死因 | 乙 listener 73.9% | 三条正交死线：Listener / 水位 / 氧气 | 最高死因 **< 45%** |

### 6.3 它服务哪条支柱（GDD §1 的删除判据）

- **P1 看不见才是恐怖**：它的位置永远不被直接告知，只能由"我在哪儿响过"推出来。推理本身就是感知。
- **P2 氧气即时间即货币**：布饵要多花一次 boom 的 7 呼吸 + 撤离的移动呼吸。诱饵不是免费的技巧，是买来的。
- **P4 地图是活的**：它的规则确定可推理（"追最强声痕"），但声痕分布每局不同 —— 符合"重连有规律、可被推理"。
- **P6 死亡是叙事**：死因永远是一句具体的话——"我在 C 舱 boom 完没走够远"。**这就是可以带进下一轮的知识。**

### 6.4 怎么验证（下一轮实验台的前置条件）

把 THE LEDGER 作为第三个变体注册进同一个 `threat` slot，但**必须先完成 P2（统一归因尺子）与 P4 的指标侧修复**，否则新一轮会重复本轮的错误：在一个"可归因 ≡ 被怪物杀死的比例"、"技巧表达度恒为 0.350"的标尺上，任何结论都不可用。

建议增补两个专为本方案设计的观测量：

- **诱饵成功率**：boom 之后 15 呼吸内玩家与该声痕的跳数距离 ≥ 3 的比例。这直接测量"玩家有没有学会这个机制"，应当随技巧档位单调上升——**它是 skillExpression 的一个干净替身**。
- **预警—行动转化率**：报警后 3 回合内玩家改变移动方向的比例。低于 40% 就说明预警又退化成背景噪音了，不必等到意外率归零才发现。
