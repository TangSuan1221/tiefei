# 接驳层：独立白模验证

入口 `/whitebox.html`；启动方式 `npm run dev` 后打开终端显示的端口。正式入口 `/` 保持原样。

## 本次实现范围

runtimeProfile 为 `standalone-whitebox`。复用 PodRun、PodView、PodSession、驾驶惯性、摄影/分析工位、5 秒曝光、12 秒本地显影、驾驶舱 UI、探照灯参数、SSAO、水体及悬浮颗粒。录像使用实际场景连续采样，不依赖外部生成服务；此配置只在白模入口生效。没有读取或写入正式存档；刷新从头开始。

基础固定摄影机始终位于艇上。怪物轮廓只在真实感光采样中显现，实时探照灯仍照亮建筑。这是本项目摄影规则的白模表达，不是移动摄影机或穿墙录像。关闭的隔离门有实际钢格栅观察窗。

地图压缩为 40×42 米的验证场，地面网格每格 2 米，净高 8 米。船体沿用 2.8×5×3 米完整水平偏航碰撞；不是摄像点碰撞。此版本不宣称完成正式章的 20–30 分钟内容量。

## 三轮摄影与可补救分支

1. **笼外威胁**：观察录像确认怪物；分析解锁设施供电路线。埃利亚斯确实被困，未设置任何身份异常伏笔。
2. **声音诱导**：配电后启动绞盘；怪物沿通路进入货仓。拖行声停止只提供拍摄时机，录像才确认入仓。直接过早关门会把怪物留在仓外；可以重新开门，再启动诱饵重试。
3. **隔离结果**：关门后拍摄钢格栅内的怪物和门体，分析当前结果才能接驳救援。旧录像仍保留历史内容，不授予新的现场事实。

错误朝向、遮挡和没有连续录像均不推进。录像证据在曝光起点锁定，分析不重新抽取结果。设施状态变化会让旧片失去“证明当前状态”的资格。正常录像可以反复播放。配电台支持补电；不通过无穷资源或预置道具证明通关。

## 验收边界

程序游玩使用真实浏览器动画帧与正常驾驶输入，不等同于首次玩家的认知负荷、情绪和心流测试。白模用来检验机制和动线，不是最终美术质量证明。关卡尚无白模专用检查点恢复；怪物是确定性诱导原型，未实现完整攻击 AI。救援为接驳状态与角色离笼，无最终动画。绝不把这些项记成已达到 3A。

实际逐轮验证结果及截图位于 `qa/whitebox/`，测试程序 `tools/whitebox-check.mjs`。最终通过项以运行报告为准，不能凭本文的设计目标推定通过。

## 本轮验收结果与未覆盖项

正常路线在 Edge 中从入口完整到达出口，`identified / powered / lured / verified / rescued / complete` 依次成立；零页面异常、正式 localStorage 全键值一致。使用正常离散驾驶输入与真实动画帧，未注入位置或进度。记录时间约 114.9 秒（游戏时间约 114.5 秒），仅代表熟悉路线的程序操作，不作为首次玩家游玩时长。三卷各有 10 张真实采样帧，曝光约 5 秒、显影约 12 秒。

`node --experimental-strip-types tools/whitebox-geometry-check.ts` 检查开/关门两种状态的泊位、往返路线、整艇扫掠转向与摄影中心视线，最终 0 失败。`npm run build` 通过。独立视觉审查直接查看了驾驶舱截图和感光帧，确认闭闸及栏后生物同时可见。

这是一段救援链的白模机制验证，不将全部正式章节 metrics 标为通过：

- MET-012：本轮有三个证据节点与串联的决策/结果链；未提供正式章要求的三个独立完整多决策循环，需扩展后重新验收。
- MET-014：设施终端采用现有 F 交互入口；未制作新物资的完整机械臂取回环节。
- MET-015：门状态及碰撞一致，开启/关闭动画与受阻检测尚未达到正式门规范。
- MET-016：确定性诱导与实体隔离已实现；完整攻击 AI、威胁预算和慢速新玩家暴露测试未覆盖。
- MET-020：一人获救分支与无异常伏笔成立；接驳动画、角色表演和正式登艇表现仍为占位。
- MET-021：本白模无检查点持久化，重启归零；因此不能据本次通过批准合入正式章节。

上述是明确保留的正式关卡验收缺口，不是对全局规则的静默豁免。人类盲测、恐怖节奏、情绪与心流不以自动驾驶或子 Agent 自评代替。
