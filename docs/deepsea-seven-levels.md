# 深海七关：叙事、美术与可玩空间规格

版本：2026-09-18。交付范围：七关主题与场景制作规格；第一关为可玩垂直切片。本文是待制作的设计约定，不是完成报告。本次只新增此文档，不修改运行时代码，不启动 Blender 或自动循环。

## 1. 定案与来源边界

**第一关确定性名称：三号采矿区·破口处理大厅。**

- 关卡标识沿用 `act.debris`，索引为 0；美术场景标识建议 `deepsea_l01_processing`。既有航线名称「作业区残骸 · 三号采矿区」可作为海图上的上级区域名称，不产生第八关。
- 七关顺序确定为：破口处理大厅 → 警戒漆分流站 → 热泉计时廊 → 四号伪补给站 → 永不停机的散热井 → 井壁伴行廊 → D-9 无垢升降井。
- 主体验确定为：人在封闭逃生舱内，经实时外置摄像机和随舱探照灯驾驶，驶入真实有厚度的水下结构。声呐用于距离、方位和失去视野后的辅助判断，不再以近场线框地图充当关卡本体。
- 保留五秒录像的「复看、数周期、留证」用途；实时镜头不必等冲洗或分析才能显示几何。录到的证据应来自同一场景状态，不能以另一张随机图改变已看见的门、箱子或尸体。

### 1.1 已读取与采用的依据

- `src/pod/content/acts.ts`：七关顺序、心理节奏、场景母题、深度、危险与机关搭配。
- `src/pod/content/route.ts`：三号舱没有透明驾驶窗；航向、调度、碰撞之间的信息关系。
- `src/pod/gen/story.ts`：七种剧情职能、必出实物、禁止放置的箱子、跨关灰港编号。
- `src/pod/content/containers.ts`、`supplies.ts`、`creatures.ts`：封条、逐次搜索、实物标识、生物形态与已有危险规则。
- `docs/narrative-bible.md`：物证先于解释；万斯索取描述而不描述自己；听者不下命令且永不完整出现。
- `docs/art-bible.md`：工业材料、深渊蓝黑、骨白、节制的锈色、声音和呼吸带来的困窘感。
- `docs/review-story-skeleton.md`：只采用已进入七关代码的剧情职能，以及「夜班通话逐渐成为交班」的结构。审阅稿中的万斯身世、地域细节和新增结局不自动成为正典。

采用 `sw-workflow` 的一次性交付流程与 `sw-premise-theme` 的前提、错误信念、价值转折方法：先明确七关逐步改变哪一个判断，再给该判断配置可见物证和可执行动作。本次不另建或覆盖总叙事圣经。

### 1.2 新需求对旧规格的明确变更

1. 旧美术圣经的「声呐屏为视觉主体」只保留在独立声呐工位；驾驶工位的视觉主体改为摄像机中的实体环境。原有 2D 绘制调用数与光照半径预算不能直接套给 Three.js 场景。
2. 原四色保留为界面、工业标记和总体色调依据；环境采用低饱和深蓝灰、灰褐、炭黑。水生发光允许极少量低饱和冷蓝白；禁止把场景变成绿色荧光洞穴。此为新环境美术扩展，不声称已修改 `palette.ts`。
3. 原始开场「电量撑不住探照灯」「先分析才生成内部」与实时驾驶冲突。后续实现需改为低功率驾驶灯可持续使用，高功率照明/录像检查承担额外消耗；首关不能因学习操作就耗尽唯一视觉来源。该变更尚未实装。
4. 保留七关既有剧情钩子，但「完成观察」应由实际镜头可见、接近和记录触发，不由打开全息地图触发。切片出口不依赖在线视频服务。
5. 旧正典为 KYRIE-9 深潜器及十九人名单，七关代码主要呈现灰港作业设施。本文不把两套历史强行合并。新增尸体是未指认的作业遇难者，不擅自替十九名船员补写死法。
6. `cre.chorus` 的七个溺者与旧正典六具唱诗班不是同一组人物；第二关只允许使用七关生物条目的远景威胁，不命名为旧礼拜堂唱诗班。`cre.hollow` 没有实体，第六关的伴行轮廓也不能未经适配就作为它的常驻肉身。

## 2. 全程叙事轴

一句话故事：平台解体后，三号舱作业员沿万斯报出的路线寻找 D-9 逃生井；每一次亲眼核对都帮他活下来，也逐步证明对方更关心他怎样走完、看见什么，而不只是他是否回家。

**前提：把他人的程序当成唯一生路，会逐渐把自己的判断也交出去。**

- 外部目标：活着抵达可上升的设施。
- 错误信念：只要照调度的指示完成清单，就一定能下班。
- 对立依据：万斯的很多建议确实有效；可核对的物证又不断否定他的解释。玩家必须有机会因自己的观察而避险，不把反抗写成任性送死。
- 终局问题：完成路线以后，是否继续把所见交给频道。七关完成不等于自动解锁旧知识树五层或八种结局。
- 每关只推进一层判断：事故可信 → 维护时间不对 → 预告像记忆 → 指令压过眼见 → 设施仍在值班 → 自己被护送 → 出口也在等待交接。
- 怪物承担生存压力，不负责解释宇宙。听者不获得身体、意图、独白或首领战。

## 3. 全关共用的物理与美术规则

### 3.1 摄像机、实体空间与尺度

- 主要活动发生在灌满海水的处理舱、管廊、竖井及其与海沟相接的破口中。每关至少一处能从真实结构看向黑水的开口，用来确认海洋环境，但不以开阔海底沙盘代替全部内部关卡。
- 初始尺度约定：逃生舱宽 2.2 m、高 2.4 m、长 3.6 m，均为制作基准，实际碰撞体由实现方统一校准。主通道净宽至少 4 m、净高至少 4 m，首关门洞净宽 4.4 m、净高 4.2 m。
- 关卡尺度必须与摄像机高度、推进速度和机械臂长度一致。人的门约 0.9 m 宽，只能作为观察口；供三号舱通过的是设备转运门，不能把潜艇开进普通办公门。
- 驾驶摄像机安装在舱前外壳，初始垂直视场角 58°；允许俯仰与转向，摄像机自由转头与船体航向必须分开反馈。避免第三人称跟随、任意穿墙自由镜头。
- 可见墙体和碰撞同源；板厚 0.15–0.35 m，转角有封边、接缝、门槛和支撑。主门后确有可驶入空间，不能用一张贴图假装通道。
- 近景机械臂可见并与箱盖/物品位置吻合。瞄准选择被墙挡住的箱子无效。临时标签只在可见且可触及对象上显示，不以整关发光轮廓替代探照灯。

### 3.2 灯光、海水与色彩

- 1120–1710 m 深度没有可用日照，不画从海面射下的阳光束，也不铺浅海泳池焦散。
- 摄像机与探照灯略错位，建议基线 0.35 m，避免全屏同轴反射雪花。首关初调：内锥约 22°、外锥约 38°；这是灯锥全角，Three.js 的半角参数应取外锥一半。有效辨形约 12–18 m，编号和锁扣约 2–5 m。
- 雾色初值 `#071014`；钢材 `#30383A`、暗橡胶 `#101619`、沉积物 `#454A48`、腐蚀物 `#624A3C`、旧漆 `#806247`、骨白标记 `#B7B9AF`。均为资产起始色，需在最终灯光与色调映射下校色，不是像素验收阈值。
- 关键物件不发光。高光来自湿润表面、镀层和探照灯反射；锈层为非金属粗糙表面，裸露钢与锈层用遮罩区分，不能所有东西套统一亮金属材质。
- 水中悬浮物有三层：贴镜头稀疏微粒、中距海雪、地面扰动淤泥。推进器靠近地面才产生局部浑浊；颗粒随运动提供方向和速度参照，不持续盖住准星和证据。
- 外部蓝黑占主体，余锈橙只出现在漆、矿物与局部反射。暗红只用于真实危险指示，不能用于所有尸体或门。发光生物以单群或单次出现计，亮点面积常态不超过摄像机画面约 1%，不照亮整间房。
- 所有亮度、距离和占比都是起始调校目标；需实机测试，不声称物理标定或视觉质量已通过。

### 3.3 深海可信度与压迫感

- 近期破口露出较新钢材，旧腐蚀与长期沉积留在原设施上。不能把刚发生的事故残骸全部做成百年遗迹；这一区别从第二关起才成为叙事证据。
- 水平面沉积明显，垂直面以接缝腐蚀、局部生物附着为主；避免把干燥陆地墙面的雨渍和苔藓无差别贴满水下墙。
- 千米深海尸体不穿普通浅水气瓶潜水服。本方案使用虚构的深水常压作业服：硬壳头盔、关节环、保护脐带、配重靴。明确这是游戏工程设定，不宣称现实设备已能在此深度安全作业。
- 尸体不持续吐泡、不游动、不固定张牙舞爪。少量布边/脐带可随水流摆动；第一关没有诈尸。
- 生物群系以无害底栖动物、胶质生物、矿物和微生物附着为底；深海热泉带可有化能合成群落意象，不放海草林、热带珊瑚礁或密集大鱼穿过设备小门。
- 压迫感来自近处舱框、狭窄视野、惯性、停不住的船体应力声和光外的未知。保持可读的近壁纹理，不能靠整屏漆黑、过强晕影或连续大幅抖动制造难度。

### 3.4 资源与状态规则

- 箱子至少有关闭、开启可搜、部分搜过、耗尽四个可见状态；箱盖、内衬、物品展示和库存结算指向同一个状态。
- 封条是风险线索，不是道具类型的绝对保证；首关两只箱子采用固定、诚实且无陷阱的教学配置。随机封条欺骗从后续关卡再开启。
- 必需钥匙、切割工具或供电不能仅在随机箱里；强制路线必须有可验证的最低物资保证，且重复读档不能重复领取同一物品。
- 跨关同一个灰港编号沿用 `stencilFromSeed` 的值；第一关不刻意强调它，第三关起让玩家在真实贴花上认出来。不要另外随机一套视觉编号。

## 4. 第一关：三号采矿区·破口处理大厅

对应：`act.debris` / `accident` / `echo-wreck`。航线模板终点深度 1120 m。主题：**事故仍然可以被相信。**

### 4.1 本关玩家经历

从裂开的设备气闸看见淹没的处理大厅，绕开倾倒支架，第一次把探照灯扫向死去的作业员；停稳、搜索物资、把无编号回波与实际镜头核对，然后手动开启转运门驶入下一段。万斯此时给出有效帮助，不揭露循环、名单或教团。

价值转折：从「眼前一团黑，无法操纵」到「能靠观察和停船取回一点控制」。唯一异常留给无编号回波；尸体与损坏设备本身均可用工事故解释。

### 4.2 固定空间骨架与坐标约定

本节坐标为导入 Three.js 后的米制坐标：+Y 向上，入口初始朝向 -Z，+X 为右舷。Blender 导出时正确转换轴向；不要再由加载端重复旋转。坐标用来冻结首版空间关系，不是现有游戏世界坐标。

主线：A 破口气闸 → B 处理大厅 → D 下沉连廊 → E 转运门前室 → F 出口接口。C 设备侧舱接在 B 左侧，往返支路不锁主线。

- A / `l01.airlock`：中心 `(0, 0, 0)`，净尺寸 8×6×10 m（宽×高×长）。入口在 Z=+5；玩家出生点 `(0, 0, 2)`，灯先照到 Z=-5 的破口门框。左右残留气闸肋条，水面和天空都不存在。
- B / `l01.processing`：中心 `(0, 0, -19)`，净尺寸 18×8×22 m；Z 范围 -8 至 -30。A 与 B 之间以宽 4.4 m 的短门套连接。地板 Y=-4，有不阻断主线的局部格栅塌陷；中央倾斜矿筛迫使一次绕行，右侧保留至少 5 m 净通道。
- C / `l01.equipment`：中心 `(-14, -0.5, -20)`，净尺寸 8×6×10 m。以 B 左壁 X=-9 附近的横向设备门接入；C 门口至柜前有足够停船空间，内部可倒车退出。支路口从大厅可见，箱子不在主线正中央。
- D / `l01.downlink`：从 `(4, 0, -30)` 通向 `(4, -4, -44)`，净宽 5 m、净高 5 m，缓慢下倾约 16°；前后截面连续封边。上方管道压低视觉空间，但不能侵入安全碰撞净空。
- E / `l01.transfer`：中心 `(4, -4, -50)`，净尺寸 10×6×12 m。终端转运门中心 `(4, -4, -56)`；控制轮在门左侧，停船后机械臂可及。门洞净宽 4.4 m、净高 4.2 m。
- F / `l01.exit`：中心 `(4, -4, -61)`，净尺寸 5×5×10 m；出口触发体置于门后至少 4 m，玩家要真正驶过门才算完成。

当前模板 `drop: 40` 与整个航段长度 380 m 不等于切片房间尺寸。切片内部只下降 4 m，其余深度差留给航段连接；后续必须统一绝对深度显示，不能入门无故跳深 40 m。避免为了凑 380 m 把首关重复拉长。

### 4.3 关键资产与确定性放置

1. **破口设备气闸** `l01.hero.torn_airlock`：A 与 B 接口；有被冲击撕开的门板、外露多层钢板和一条断开的管线。首关不用「向内/向外卷边」替旧知识树自动授予真相。
2. **倾斜矿筛/矿物分离机** `l01.hero.separator`：B 中心略左 `(−2, −2.1, −19)`，占地约 6×7 m，高 5 m；倾角约 12°。它承担遮挡、绕行和规模感，不是装饰小盒子。
3. **遇难潜水作业员** `l01.body.diver01`：B 右后侧 `(5.8, −3.0, −23)`，斜靠低矮支架；头盔完整、面罩暗，身长约 1.9 m，脐带延伸到坏掉的工具端口。从绕行主路 4–7 m 内能照见；靠近可观察装备破损，但不强制搜尸、不发任务钥匙、不显示实名。
4. **应急补给箱** `l01.cache.supply01`：B 右侧停靠凹位 `(6.5, −2.3, −14)`，尺寸约 1.4×1.1×0.9 m，箱盖向外打开时不挡驾驶路线。第一批为 `sup.cell`×1、`sup.lure`×1。使用既有 `wr.module` 首批内容，作为同一份补给，不再从残骸菜单重复发放。
5. **工具箱** `l01.cache.tools01`：C 里侧支架约 `(-16, −1.8, −22)`；玩家进入支路并停稳可搜。内容 `sup.tape`×2、`sup.cutter`×1，对应既有 `wr.module` 第二批；映射为同一两批物资的不同实体位置。切片不改造为随机标准箱的另一套掉落。
6. **普通机械转运门** `l01.door.transfer01`：E/F 接口，左侧外露控制轮、上下导轨、锁舌可见。首关是卸载锁舌后滑开的普通门，不引入第五关的切割锁；拿不拿工具箱都能通关。
7. **无编号回波观察点** `l01.evidence.echo01`：D 入口前朝向 E 的视线上，允许声呐报告未知回波，但实体镜头看见黑水、门框和漂浮物，没有完整怪物。采用 `cre.hollow` 的无实体表现，观察记录写「镜头里没有对应目标」，不得为它建一个实体人形。
8. **矿壳蟹群** `l01.fauna.crab01`：B 下部管口附近，3–5 只，避开箱盖和门轨；低矮移动、不自发光。用于区分「小东西在动」与危险。
9. **磷光水母小群** `l01.fauna.jelly01`：D 外侧破损检查窗后的黑水中，1–3 只短暂经过；不位于可穿过的实体玻璃里。亮度只够辨认局部伞盖，不给路线照明，也不把擦碰充电当真实海洋规律。
10. **沉积与损伤组**：梁底锈结、地板细泥、一个倾倒货架、两段悬垂线缆、松动布条。门洞、出生点、箱前停靠体积和安全通道内禁放随机硬障碍。

### 4.4 可玩闭环与失败边界

目标体验时长 8–12 分钟，为设计目标而非实测。

1. 启动驾驶镜头：近处看得见门框与地板，推进/刹停/转向立刻改变同一 3D 场景中的透视和视差。
2. 穿过破口：学会绕开矿筛，不通过 UI 选择房间来瞬移。
3. 灯扫到遇难者：短暂停留；可选择继续。观察不会触发诈尸或强制扣除开门资源。
4. 至少一次实物搜索：瞄准箱子 → 停到机械臂范围 → 撬开 → 看到物品 → 收回。必须看见箱子变空与库存增加，并可选取回电池测试资源闭环。
5. 完成一次回波观察记录：可提交五秒录像或确定性本地记录；不要求打开线框屏，也不请求外部生成视频才能过关。万斯只催事故报告。
6. 操作转运门：锁舌退回 → 门滑开 → 灯照到门后实际空间 → 驾驶穿过出口。未开门时不能穿透，出门后才出现本关完成反馈。

垂直切片必测搜索闭环可以设为本次教学目标；正式流程是否强制搜箱由主实现方决定。任何情况下工具箱不构成软锁，尸体也不是必搜钥匙。

首关固定布局与无陷阱掉落；可改变的只有非交互微粒和小动物相位。遇难者、门、箱、回波观察点不可随机换位。记录与重进应保持物品领用、开门和已观察状态一致。

### 4.5 首关声音与对白位置

- A：舱内呼吸、液压和金属轻响压过外界；万斯给一次可信的操作帮助。
- B：微弱管道应力声提供大厅尺度；搜箱时有伸臂、碰撞、锁扣断开、回收四段声音。
- 尸体观察：不额外插入惊吓音效，不由万斯替玩家认人。
- D：水母经过时让机械背景稍稀，保留呼吸；观察无编号回波后只留一个短停顿。
- E：门的机械位移和导轨声应与真实开门时间一致。过门后恢复万斯短句，给下一关方向，不播放世界观说明片。

## 5. 第二关：警戒漆分流站

对应：`act.pipes` / `too-ready` / `paint-fork`。模板深度 1280 m。主题：**废弃设施里，有一处维护得太及时。**

- 空间：狭长进水管廊 → 直径约 14 m 分流大厅 → 镜像的左右设备通道 → 有漆侧阀室 → 汇合出口。两支路的净空、长度和支架节奏一致，别用大小或箱子多少提前泄露答案。
- 关键标志：一侧内壁有连续余烬色警戒漆；另一侧保留磨损编号但不形成更醒目的导航箭头。漆是反射材质，灯照上才显；新补漆与旧锈之间的边缘形成证据。
- 玩家动作：用灯观察两侧 → 记录正确漆线 → 驶入阀室 → 操作对应阀门。必须有文字/形状补充线索，例如同一侧的重复漆带缺口，供色觉差异玩家核验；补充线索不能是地图上的答案。
- 尸体：最多一具旧常压作业服，放在分叉之前的检修壁龛内，不摆在真假路线末端当答案。脐带被切断且覆有沉积，表示早于今晚事故，不认定死者身份。
- 物资：阀箱提供 `sup.filter`、`sup.stim`，与模板相符；阀门必需操作不消耗随机药物。两支路都不放首关式教学宝箱。
- 群系：支架背面的薄生物膜、管口矿壳蟹。无害背景少量；已有 `photophobe` 避光/照明风险仅在玩家读到漆之后启用，首次分叉不得被强制关灯遮掉。
- 灯色/材质：煤灰管道、陶瓷般发白的结垢、窄条旧余烬漆。关闭灯后只剩极弱机械指示点，不给双支路常驻不同颜色。
- 叙事转折：万斯的解释仍可能合理，但快得像早知道玩家会问。物证是「漆比周围新」，不是直接发现邪教徽记。
- 复用：墙板、门框、管道、阀轮、首关作业服姿态变体、医疗小物件。
- 独有：对称分流结构、大号浆料分配阀、漆层新旧剥离贴花、遮光检修隔栅。

## 6. 第三关：热泉计时廊

对应：`act.vents` / `path-remembers` / `period-heading`。模板深度 1460 m。主题：**玩家学会了节奏，路线却像早已记住玩家。**

- 空间：钢框与岩壁交错的破损热交换廊 → 周期喷流横穿的单一间隙 → 安全等待凹位 → 地热桩侧室 → 裂谷端出口。必须让海沟岩壁进入真实房间，不是给钢走廊换一层橙色贴图。
- 关键标志：喷口对岸矿物壳、可见停歇窗口、侧室地热桩上第一次明确重复的灰港编号。喷流位于万斯预报航向，不能任意种子生成到相反侧。
- 玩家动作：停在掩护内观察一完整周期 → 选择停歇窗口通过 → 决定是否承受充电泵噪音。录像需带记录时间；回放是过去，实时镜头给当前喷流，避免拿旧录像当实时安全窗口。
- 尸体：一具旧作业服卡在已停用旁路的支架上，矿物覆盖明显；不在唯一喷口正中，避免成为必须碰撞的路障。
- 物资：工具箱 `sup.cell`、`sup.sealant` 在地热桩底座；充电接头与箱子是不同交互，别一次点击同时白拿全部。
- 群系：白色细管状附着群、低矮贝类与热泉周缘小虾的设计意象，集中在温度过渡带，喷口中央无生物。默认无自发光；黑烟、热扰动和探照灯反射承担视觉变化。
- 灯色/材质：玄武岩炭黑、硫化物灰、低饱和矿物褐。热泉不是熔岩灯，不把喷口做成橙红火焰。
- 危险控制：主机关为喷流，既有 `laser` 只可作为已标识的检修扫描设备，不叠成连续发光激光网。钩灯仅在相邻黑水出现可回避的轮廓，不同时遮住喷口计时信息。
- 叙事转折：万斯准确预告等待位置，玩家在桩上找到重复编号；二者共同产生「不是第一次走」的疑问，暂不解释轮回。
- 复用：支架、管道、工具箱、门框、可充电接头、作业服。
- 独有：岩壁模块、喷口烟囱、周期羽流、矿物壳、热泉群落、地热桩主体。

## 7. 第四关：四号伪补给站

对应：`act.mimic` / `dont-look` / `true-charge`。模板深度 1560 m。主题：**救援者第一次要求玩家以指令替代眼见。**

- 空间：轴线规整的供给甲板 → 左右等尺寸补给开间 → 中央独立真充电桩 → 后方出口。两开间约 10×6×10 m；玩家必须能在中线安全处检查，而不是进嘴里才能识别嘴。
- 关键标志：真站有接缝、门铰链、密封压条、电缆入口和编号；伪站缺乏可开合结构，中心一枚钩灯亮点随水缓慢移动。远距离都像块体，近距离材料与构造不一致。
- 玩家动作：选择是否违背「别拍两边」 → 检查真实硬件 → 在中央桩充电 → 决定是否偏航取物。照到假站不得立即无前兆杀死，先有诱灯移动或表皮收紧的可见警告和退路。
- 尸体：真补给侧隔栅后可见一具封存作业服，旁边空挂架尺寸相同；先不显示内部人脸。伪站不再另堆血淋淋尸体泄露答案。
- 物资：真电池组两批 `sup.cell`+`sup.pulse`、`sup.flare`+`sup.wax`；中央桩负责充电，不能因玩家拒绝冒险搜两边而断绝基本出路。
- 群系：真侧极少附着，假侧为接缝处收缩的暗色膜；普通小鱼绕开假侧，但这是辅助细节，不是唯一辨认方式。
- 灯色/材质：暗灰钢与低饱和组织膜接近；冷白诱灯只是一小点，真站工业灯不闪成「安全绿色」。
- 既有雷区仅放在外缘废弃供给泊位，并有实体线缆、壳体和标记；中央停靠与必要检查点不能被看不见的地雷覆盖。
- 叙事转折：玩家可亲眼证明指令不充分，却仍用万斯指向的真桩活下来。这是中点，不揭晓万斯身世。
- 复用：两套设备间、门框、箱体、电缆、充电接头、作业服。
- 独有：伪站表皮与口腔入口、移动钩灯、对称站体外壳、四号桩标识。

## 8. 第五关：永不停机的散热井

对应：`act.fans` / `still-running` / `fan-and-cut`。模板深度 1680 m。主题：**人已不在，工作程序还在执行。**

- 空间：叠层工业中庭 → 风扇等待室 → 直径约 12 m 的低速水下散热叶轮 → 下层切割门前室 → 检修出口。叶轮缺口必须能容纳完整船体，并提供足够通过时窗；不是只让摄像头穿过一条缝。
- 关键标志：规律转过的缺叶口、门一侧的局部减薄腐蚀、不同年代检修牌层叠、沿用的灰港编号。
- 玩家动作：看缺口周期 → 分辨真实通行方向与万斯的 210° 建议偏差 → 过叶轮 → 灯照到门的薄弱侧 → 一次切割。既有安全航向为 310°，关卡与局部坐标换算必须一致，不能只在台词里宣称撒谎。
- 尸体：两具旧作业服固定在停用的上层检修平台；主路只能看到其中一具，另一具从门前回望才出现。都不进入旋转叶片，不用飞散残肢做常驻特效。
- 物资：门前设置可核验的一次性切割器保证，不能把唯一切割器锁在必须用它打开的门后。模板检修门奖励的 `sup.cutter`、`sup.cell` 应作为开门后的补充，或明确改放门前；两种方案不可重复领取。
- 群系：压差区的丝状附着、格栅上的矿壳蟹、远处铁织借旧船板产生的运动。生物色彩最少，机器运动最多。
- 灯色/材质：旧油污黑、剥落灰漆、局部低亮度余烬工作灯；灯扇扫过的阴影来自真实叶片，而非循环屏幕遮罩。
- 危险控制：已有挤压机置于独立侧线或在叶轮教学结束后引入；不把叶轮、挤压与铁织同时堆在一个不能停车的狭口。
- 叙事转折：新旧检修牌与仍在供电的机器证明事故不是工作终点；不给玩家直接念出教团会议记录。
- 复用：梁柱、墙板、控制轮、工具柜、作业服、编号贴花、船板材质。
- 独有：大叶轮及缺叶、旋转轴、切割门薄弱板、叠层井框、铁织的外板组合形态。

## 9. 第六关：井壁伴行廊

对应：`act.watcher` / `escort` / `watcher-face`。模板深度 1710 m。主题：**没有攻击的跟随，比追逐更像安排。**

- 空间：贴海沟井壁的长廊 → 三个间隔观察窗 → 一段立体转折 → 低处狭窄停靠位 → 井口前通道。外面是不可测黑水，里面持续给出墙、扶手、门框以判断位移。
- 关键标志：每扇窗外同一距离的陪行位置；第一窗是鱼群，后一窗鱼群消失但有轮廓停着。窗之间有实体墙段，伴行物不能透墙显示，也不能在玩家转头时无理由瞬移到脸前。
- 玩家动作：停船看距离是否保持 → 调整低功率侧灯 → 记录一次伴行观察 → 保持距离离开。避免「不准开灯却必须看清脸」的软锁：不准的是强探照长照；允许短时低功率检查和相机增益。若仍无法看清，报告「无法辨认」也可完成观察，不强制猜身份。
- 实体边界：独有伴行轮廓暂作为关卡事件表现，不直接替换 `cre.hollow` 的空回声定义。最低交付可只做隔窗断续的工装轮廓和失焦，禁止建听者真身或提前把面孔确定为玩家。
- 尸体：全关新增尸体为零。让玩家失去「看一具尸体就知道那是过去的工人」这一判断方式，不用第三种尸体堆增加强度。
- 物资：主路和出口零货箱，严格保留 `forbidExitCaches`；靠前关预算提供通过条件，不能临时在出口塞救济箱掩盖失衡。
- 群系：前三分之一有一小群低亮度灯笼鱼，随后显著稀疏；不加新攻击型背景生物。漩流只在实体破口外，近壁安全带与水流方向可由微粒读到。
- 灯色/材质：全程最冷、最低饱和的一关；观察窗盐垢、金属接缝和外水分层清晰。轮廓由侧向反射勾出，不是自发光幽灵。
- 叙事转折：万斯要求描述，伴行物等待观察结束。玩家可以怀疑自己正被送往岗位，但没有独白替玩家做结论。
- 复用：通道、观察窗框、船板、线缆、鱼群、微粒系统。
- 独有：长形井壁模块、三窗节奏结构、伴行事件轮廓与受遮挡路径、局部旋流。

## 10. 第七关：D-9 无垢升降井

对应：`act.lift` / `too-clean` / `glyph-barge`。模板深度 1585 m；此关是向上，不是再往下。主题：**出口真实存在，但它过分像早已准备好的工位。**

- 空间：粗糙检修入口 → 侧面驳船观察口 → 图案锁门 → 完整圆形承压环 → 垂直升降井。前室约 16 m 直径，井内径建议 10 m；沿井壁检修梯给尺度，但玩家仍在舱内驾驶或进入升降承台。
- 关键标志：驳船舷侧三个可读符号、对应的机械图案锁、与前六关同一体系的灰港编号、几乎无泥的承压环。三个符号固定为本关数据给出的序列，美术不能另写一套装饰字符。
- 玩家动作：灯照并记录舷侧 → 在锁上逐项比对 → 开门 → 将舱移入承台/井内 → 在上升承诺前处理无线电选择。看到井口不等于自动通关，关掉无线电也不能自动满足旧结局全部知识条件。
- 尸体：井内及前室没有新增尸体。驳船可有一套空作业服固定在支架上，但不加身体，把第六关的无法确认延续下去。
- 物资：可选 `sup.stim` 只在井外驳船；井内、升降承台和最终出口周围零货箱、零散落残骸，严格保持 `cleanShaft`。
- 群系：井外可有一层稀薄胶质生物或 `veil` 风险，井内没有附着群。干净的圆井需要前六关的生物/沉积对照才成立；不能拿一面发光白墙代替清洁实体材质。
- 灯色/材质：无锈或少锈的灰钢、完整橡胶密封、骨白机械数字。允许更均匀的低照度检修灯，但出口上方仍是黑水，不演成明亮神殿。
- 叙事转折：同样的接头、编号和工作位置出现在所谓救援设施。最终频道选择由实现方接已有结局系统或明确标注的暂定收尾；本文不宣布「万斯曾是三号舱」已经成为代码事实。
- 复用：门、图案锁输入件、供电接头、船板、编号、空作业服。
- 独有：完整圆井环、升降承台、井内导轨、驳船舷侧及符号、洁净密封组件。

## 11. Blender → Three.js 资产交接约定

以下是给后续制作方的建议交付格式，本次未执行建模或导出。

### 11.1 首批制作优先级

P0 可玩必需：墙/地/顶实体模块、厚门框与破口气闸、倾斜矿筛、普通可动转运门、两只可动箱、深水作业服遗体、四类可见物品（电池、诱饵、胶带、切割器）、机械臂交互锚点、碰撞几何。

P1 深海可信度：管道接头、线缆、格栅、淤泥贴层、矿壳蟹、水母、悬浮物与推进器扰泥；P1 不能用来拖延 P0 的可玩闭环。

P2 全程拓展：分流阀 → 热泉和充电桩 → 伪站 → 叶轮与切割门 → 伴行轮廓 → 无垢升降井。每完成一关，先复用首关模块再做独有资产，避免七套互不兼容的墙。

### 11.2 文件、对象和枢轴

- 建议导出：`deepsea_shared.glb`（通用道具/结构）与 `deepsea_l01_processing.glb`（首关独有结构和摆位）；后续 `deepsea_l02` 至 `deepsea_l07`。运行时实际 public 路径由主实现方统一。
- 对象命名：`geo_*` 可见几何，`col_*` 简化碰撞，`int_*` 交互锚点，`spawn_*` 出生/生物锚点，`trigger_*` 观察与出口区域。纯空对象锚点需要导出验证，不能只存在于 Blender 视图中。
- 门板、锁舌、箱盖独立网格与正确枢轴；动画节点或命名动作可分别驱动 `door_open`、`crate_open`。基础原型允许程序动画，但不能把门板合并进静态墙体后让整面墙移动。
- 通用墙与管道使用 1 m 模数、4 m 主单元；重复件共享网格和材质。遗体优先静态姿态，脐带单独低骨骼/程序摆动，首关无需完整角色战斗骨骼。
- 贴花保留实物尺寸和语义来源：警戒漆、编号、符号序列应可由关卡数据覆盖。不要将唯一答案烧在不可控的整关颜色贴图里。
- 贴图最低含基础色、粗糙度、金属度、法线；贴图色彩空间按用途设置。海水体积、探照灯、微粒及威胁事件由 Three.js 实现，不把静态发光圆锥烘焙成永远穿墙的「光」。

### 11.3 初始预算与降级顺序

- 首关可见几何初始目标不超过约 35 万三角形、120 次绘制调用；共享常见材质约 12–18 个，普通贴图 1K、英雄资产 2K。此为待测建议，非现有性能实测。
- 仅主要探照灯优先投射阴影；微小生物发光默认不创建逐只点光源。重复管道、螺栓、生物实例化。
- 若帧率不足，依次降低粒子数、阴影分辨率、后处理与远处细节；保持近处门框、箱子状态、尸体轮廓、碰撞与证据清晰度。决不降级回线框主画面。
- 固定测试分辨率和设备后再制定性能门槛；旧美术文档的 60.3 FPS 不是新 Three.js 关卡的成绩。

## 12. 验收方式与已知待接工作

### 12.1 首关必须实机证明

- [ ] 开局直接进入摄像机驾驶视野；无需开全息地图也能穿过 A/B/D/E/F。
- [ ] 左右平移、前进和转向产生真实视差与遮挡；灯随船/云台移动，不是全景图取样。
- [ ] 近处墙、顶、门框有厚度和材质，撞击发生在看见的实体上。
- [ ] 主路能照到一具符合深海作业设定的遗体，支路能找到第二只箱。
- [ ] 两箱可分别打开、取出对应物资、显示耗尽；重开面板/读档不会重复获得奖励。
- [ ] 机械臂不能隔墙搜索，箱盖与门板不穿进驾驶舱或堵死退出路径。
- [ ] 灯下能认出至少一种无害底栖生物；荧光仅为偶尔出现的少量点状生物，不是环境泛光。
- [ ] 无编号回波观察在本地可完成，录像与实时门/箱状态一致，不依赖网络生成。
- [ ] 门从闭合到打开有真实几何变化，玩家实际驾驶过门，收到明确关卡完成反馈。
- [ ] 不搜尸、不取得可选切割器也有通路；故障或资源耗尽后有清晰恢复/重试方式。
- [ ] 调低颗粒和抖动后仍能感到闭塞，证明压迫感不是单靠遮挡屏幕。

### 12.2 视觉检查镜位

固定五个游戏内镜位：A 看破口；B 绕矿筛同时看到遇难者；C 开箱时机械臂与物品同框；D 看黑水中的微弱水母；E/F 看打开的门与门后空间。另录一段不中断的完整驾驶、搜索、开门、出关视频。

这些素材用于核对规格和可玩性。当前没有用户提供的真实深海参考图片，也未进行参照图盲评；不得写「已达到 AAA」「照片级已验收」或拿首关效果推断七关均已完成。后续若引入研究机构深海影像或商业模型，应记录出处、许可和使用范围，再开展独立视觉评审。

### 12.3 主实现方需要处理的接口差异

- 将「先分析才出现内部」迁移为「先观察/记录才完成证据」，保留实体空间始终存在。
- 为低功率驾驶灯、高功率检查与录像分别定义消耗；修改不适用的旧无线电提示。
- 同步真实三维碰撞、停船搜索距离、机械臂锚点与实体物品归属；避免菜单残骸和实体箱双发奖励。
- 后六关可变化非关键装饰，但每关必出实物与通路必须保持；第一关布局固定。
- 解决全局航向与局部场景坐标、模板深度与关内下降量的对应；保留第五关的可验证航向矛盾。
