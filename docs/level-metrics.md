# 全局关卡 Metrics · v1.0

更新：2026-09-29。适用：本项目所有新增、重做及待验收关卡。主产品基准为 `/` → `PodRun` → `PodExpedition`；不是独立 `/expedition.html`。本文件制定设计验收规范，不意味着旧关卡已经全部合规。

本文件是本地 RAG 的权威关卡规则源。代码事实标为 `IMPLEMENTED`，本轮制定的强制设计标准标为 `REQUIRED`，未经实现的能力标为 `NOT_IMPLEMENTED`，冲突标为 `GAP`。状态不能互换：代码说明现在怎样工作，REQUIRED说明后续关卡必须怎样设计。新用户决定优先；改变底层机制后须同步规则与检索索引，不允许在剧情里偷偷假设能力。

## MET-001 运行入口与规则优先级

状态：REQUIRED。关键词：入口 runtime 主游戏 独立探索 七关 五关。

每个关卡设计必须声明 `runtimeProfile`、关卡编号、设备集、规则版本。默认 `main-authored`（主游戏）。`standalone-expedition` 是独立探索；`legacy-volume` 为旧生成器；`preview` 为场景预览。四者的距离、碰撞、时间和存档不能混用。

新增 `standalone-whitebox`：`/whitebox.html` 是第一章独立可玩验证，复用主游戏工位、驾驶和基础摄影，使用本地真实采样录像；不读取或写入正式存档。几何、诱导行为与补给为实验配置，不能自动推广为正式关卡已通过。实现与例外见 `docs/whitebox-chapter-one.md`、`src/whitebox/site.ts`、`src/whitebox/main.ts`、`src/whitebox/world.ts`；实际验证见 `tools/whitebox-check.mjs`。

当前代码仍有七关内容；用户选定的故事提案为五关。五关不是已完成的代码迁移。全局metrics与关卡数无关；不准把旧七关房数、剧情和怪物配置复制成新五关的硬要求。第一关的信任要求只适用第一关，不能扩展为全游戏禁止谎言。

依据：`src/pod/view/deepsea/pod-expedition.ts`（PodExpedition）；`src/pod/content/expedition.ts`；`docs/chapter-one-rescue-revision.md`。

## MET-002 船体碰撞基准与现有差异

状态：IMPLEMENTED / GAP。关键词：船体 包络 碰撞 半径 HARBOR_HULL POD_R。

主游戏首关采用 `HARBOR_HULL`：宽2.8m、长5m、高3m；偏航扫掠步长不大于0.5°，包络是偏航OBB，不是包含纵倾、附着物及机械臂的完整刚体。

主游戏后续关卡仍用0.28m操作半径和高度中心范围−1.25至+2.75m；旧生成器 `POD_R=1.2`；独立预览可用0.85m。这些都不是“潜艇真实外形可以缩小”的许可。所有新关卡按2.8×5×3m基准做实体通行验收，带挂件另算；后续碰撞未统一属于现有实现缺口，不能宣称已经全局修复。

依据：`src/pod/sim/harbor-navigation.ts`（HARBOR_HULL、sweepHarborHeading）；`src/pod/view/deepsea/pod-expedition.ts`（canMove、turn）；`src/pod/gen/interior.ts`；`src/pod/view/deepsea/preview-collision.ts`。

## MET-003 航道、门洞与转弯净空

状态：REQUIRED。关键词：通道宽度 门洞 净高 掉头 净空 metrics。

尺寸按最终碰撞和门框内缘量，不按美术外框或房间名义尺寸量。普通主航道净宽≥8m、净高≥6m；有意压迫的短直段净宽≥5.5m、净高≥5m，必须可倒退且不可兼作强制180°掉头点。直行门洞设计下限4m宽×4m高，对基础船体各侧留0.6m、上下各0.5m余裕；弯前、挂件、侧向过门必须加大。

基础掉头区采用直径≥12m；救援接驳及带侧挂件预留≥16m，主路净宽先取≥9m，再按真实挂件包络复核。12/16/9m是本轮设计标准，不是代码常量，也不是对任意附着物的保证。

纯水平原地偏航的理论包络直径约 `sqrt(5²+2.8²)=5.73m`，但不能拿这个零操作余裕的下限代替实玩标准。连续平移、偏航、升降和正反向返程都须验收。碰撞网格简化不构成缩小通道的理由。

依据：`src/pod/sim/harbor-navigation.ts`；`docs/level-01-design.md`（旧灰盒建议，非实现证明）。

## MET-004 驾驶速度、扫掠与路线时间

状态：IMPLEMENTED / REQUIRED。关键词：速度 1.6 倒车 刹车 航程 时间。

主游戏PilotMotion前进夹紧上限1.6m/s，倒车下限−0.65m/s，有加速与阻力；前进上限不是整段平均速度。偏航输入36、阻尼2.4对应持续输入稳态约15°/s。主游戏平移分段≤0.08m、升降分段≤0.04m；碰撞停止前进但应保留转向和倒退脱离。

关卡时间以可达路径长度、加减速/掉头、机械臂、曝光、读片、补救分别估算，并以试玩复核。`路线米数/1.6`只能作为无障碍全速下界。不得按经验速度强制凑20分钟；不得通过锁定倒计时保证关卡时长。

依据：`src/pod/sim/pilot.ts`（PilotMotion.step）；`src/pod/view/deepsea/pod-expedition.ts`（move、moveVertical）；`src/pod/sim/run.ts`（driveBlock）。

## MET-005 操作距离与摄影距离必须分开

状态：IMPLEMENTED / REQUIRED。关键词：3.4米 6.5米 交互 距离 射线 机械臂。

当前主游戏 `PodExpedition.aim` 射线最远3.4m，首个可见实体遮挡后方交互。旧 `ARM.reach=6.5m` 不能用作当前设施F交互距离。设计普通操作站时，目标表面到合法艇位宜在2.0—3.0m，且整个船体不穿墙；最终验收严格≤3.4m并无实体遮挡。

摄影机位可以比操作点远。不得因为P2在8—12m处能拍到闸门，就让玩家直接操作同距离的闸门：必须设置3.4m内的真实控制终端，或先靠近接线再退回拍摄；“远程控制”必须已有实现与接线状态。机位表必须同时写摄影目标距离与控制台表面距离。

依据：`src/pod/view/deepsea/pod-expedition.ts`（aim、interact）；`src/pod/sim/manipulator.ts`（ARM）。

## MET-006 摄像视点、视场与无遮挡

状态：IMPLEMENTED / REQUIRED。关键词：摄像头 视点 FOV 观察孔 穿墙 云台。

主游戏相机位置等于当前驾驶位置；当前主游戏垂直视场 `64/camZoom` 度，基础倍率1时64°。云台在艇朝向上叠加角度，不是可脱离艇体移动的摄影头。旧camera-room光心也明确没有安装偏移。不得以“相机在夹层里、玩家在外面”解释同一固定摄像头的特殊视线。

每个关键机位必须登记位置、朝向、倍率、目标尺寸、遮挡体、光照、证据内容、返回时状态变化。机位只能经实际驾驶获得；所有关键物体和锁销必须落在真实视锥内，不能在结果片切成全知镜头。镜头参数上限不等于可读距离。

依据：`src/pod/view/deepsea/pod-expedition.ts`（camera、pose）；`src/pod/view/camera-room.ts`（cameraEye）。

## MET-007 光照与证据可读性

状态：IMPLEMENTED / REQUIRED。关键词：灯光 探照灯 摄影距离 可读性。

主游戏探照灯声明距离32m，这是灯的作用范围，不保证32m处可读细节。首关旧救生舱取证判定允许3—65m、稳定≥0.75s，仅属于该大型目标；禁止把65m作为全关卡通用细节摄影范围。该取证函数保存lightOn但目前没有把它写入valid条件，不可宣称所有无灯照片都会被逻辑拒绝。

新关卡关键动作机位初始设计距离6—12m；更远或更小目标必须靠近、变焦或另设真实机位。每条决定性证据在实际输出画质中至少连续可判读1秒，目标关键特征建议≥24px；这是设计验收阈值，不是当前渲染器保证。默认缩放下文字/可选描述可读，提供暂停复看，不用一帧彩蛋做主线唯一信息。

依据：`src/pod/view/deepsea/pod-expedition.ts`（lamp）；`src/pod/sim/harbor-progress.ts`（HARBOR_CAPTURE_LIMITS、captureHarborEvidence）。

## MET-008 信息分层与摄影不可替代性

状态：REQUIRED。关键词：声纳 实时视野 怪物 摄影必要性。

设施、门和可操作物可以实时观察；现有猎手规则把生物形态留给录像，声音/字幕/匿名回波承担即时预警。该表现规则不是现实光学解释，也不自动适用于所有新NPC。主游戏当前声纳范围24m、扫描周期2.4s；不能依声纳直接认证人格、身份或精细锁位。

每个主线摄影环节必须写清实时视野缺少的决策信息，以及录像提供它的原因。若在目标入口持续开灯就能取得全部相同信息，必须重设计或明确修改机制，不准仅锁按钮迫使看片。不准凭“很黑”自动推导相机能透墙。

依据：`docs/monster-ai.md`；`src/pod/sim/navigation-sonar.ts`；`src/pod/view/deepsea/pod-expedition.ts`。

## MET-009 五秒曝光与动作互斥

状态：IMPLEMENTED。关键词：曝光5秒 拍摄 机械臂 同时 操作 停船。

曝光5秒；须处于site、有电、机械臂已收回，且没有进行中的曝光/显影。曝光期间必须留在camera工位，离开会废片；driveBlock锁驾驶，设施交互也受该锁约束。机械臂伸出时beginShoot直接拒绝。观看回放时驾驶与外部操作被阻止。显影本身不锁驾驶，其他条件仍可能锁定。

因此禁止设计“伸着机械臂操作并同时录像”“曝光时开船追随怪物”“开着回放操作外部设施”。可行默认序列：先执行并收臂 → 面向结果稳定物 → 停船曝光 → 显影期避险/做允许的准备 → 去分析台确认 → 返回实时操作。若必须记录动作全过程，须先实现自主设备事件或延时触发，不能把未实现同步动作写成现成能力。

依据：`src/pod/sim/run.ts`（beginShoot、tickShot、driveBlock）；`src/pod/view/deepsea/pod-expedition.ts`（interact）。

## MET-010 显影、网络与复拍串行

状态：IMPLEMENTED / REQUIRED。关键词：显影12秒 超时100秒 网络 复拍 单相机。

主游戏当前最大显影等待DEVELOP_TIMEOUT=100s；具备siteEvidence的本地底片在显影经过12s后可ready，远端结果另行处理。不能把12s当所有视频返回保证，也不能把100s称作正常剧情节拍。已有曝光/显影未结束时不能开下一卷；本地底片ready不等于远端shot.phase一定已ready。

新关卡不得把网络请求时长当敌人推进或必死窗口的依据。关键证据必须有可播放的确定性本地/受控录像路径，不能用静态首帧冒充成功录像。设计多次复拍时应覆盖最快、12s本地、100s超时和服务失败情况；未实际验证前标为缺口，不宣称流程已适配。

依据：`src/pod/sim/run.ts`（DEVELOP_TIMEOUT、tickShot、settleShot）；`src/pod/sim/harbor-progress.ts`（resolveHarborEvidence）。

## MET-011 录像快照、真实结果与知识状态

状态：IMPLEMENTED / REQUIRED。关键词：快照 结果录像 RAG 剧情 状态 可重放。

曝光时锁定现场事实与目标可见性，片匣回放不能读取返片时的新世界来改写旧录像。当前主游戏记录曝光快照与采样帧，首关需要有效曝光和可播放录像后显式分析才授予事实。

新结果片必须对应已经发生的动作。物理状态、已获得证据、向万斯提交的信息分开存储；观看录像不产生之前不存在的感染、死亡或成功锁门。AI输出不得决定身份与生死；关键动作、编号和阀位必须用受控素材/证据层保证。失败、静态图、空mediaId不能被当作录像成功。

依据：`src/pod/sim/run.ts`（beginShoot、archiveTape、analyze）；`src/pod/sim/harbor-progress.ts`。

## MET-012 全关卡摄影循环配额

状态：REQUIRED。关键词：循环 配额 结果片 分支。

每关至少3个主要完整环节：拍摄 → 返回侦察片 → 观察后行动 → 取得结果片 → 依据结果再次行动。每关至少2个环节改变人物/路线/物理隔离/资源/后续威胁中的一项，至少1个提供有代价的补救；不要求每关都突然出现坏结果。

每个环节需有可执行的正常结果、由实际条件导致的异常结果或证据不足结果。正常准备允许一次成功；不要为凑片数固定制造挂钩、软管、门锁三连故障。每关至少两个不同决策动词，例如定位+隔离、试验+救援，不能全是拍门开门。

依据：用户指定的五关摄影循环；`docs/story-camera-loops-2026-09-28.md`（叙事参考，动作须先经过MET-009审查）。

## MET-013 时间差、阅读与补救窗口

状态：REQUIRED / GAP。关键词：等待 安全窗口 暂停 阅读 倒计时。

当前主游戏frame持续tickThreat/tickShot/tickArm，观看与站位不等于全世界暂停；独立探索的面板暂停规则不能套用。此前剧情稿“阅读时不计紧迫时间”属于未实现要求，不可用来保证安全。

高风险环节必须计算 `T保留 ≥ T曝光 + T取得可用证据 + T读片预算 + T回到控制位 + T操作 + T余裕`。原型读片预算至少15s、余裕至少5s，最终经慢速玩家测试调整。需要动作过程而现有快照只记录起始状态时，应改拍稳定结果或先实现持续事件记录。

优先使用持续诱导、实体笼子、止回机构、机械锁保持局面，不以“片里还没越线”推断现在仍能补救。已经越界的对象不能被关门动作倒回去。若最长网络延迟无法纳入窗口，必须采用本地确定性证据或暂停危险的已实现机制；不能把安全责任交给网速。

依据：`src/pod/sim/run.ts`（frame、tickShot）；`src/pod/view/deepsea/expedition-runtime.ts`（paused）。

## MET-014 机械臂时长、目标与收回

状态：IMPLEMENTED / REQUIRED。关键词：机械臂 伸出 收回 抓取 入库。

ARM常量：伸出3.4s、夹取1.8s、收回2.6s，基础运动段合计7.8s，不包含瞄准、翻找、卡爪和玩家输入。主游戏取物需要照明与供电；成功夹住仅生成pendingCargo，收回完成才入库。中途切换目标不可把道具瞬移到艇内。

每个关键取物点必须给出≤3.4m合法操作位、臂运动净空、至少一次失败/收回路径及备用资源。关键通关物不能只有一次不可逆随机夹取机会。机械臂毁损后的修复回路必须真实可达；旧臂能伸到6.5m不改变当前场景瞄准距离。

依据：`src/pod/sim/manipulator.ts`（ARM）；`src/pod/view/deepsea/pod-expedition.ts`（interact、armEvent、serviceHarbor）。

## MET-015 门、机关与操作成功语义

状态：IMPLEMENTED / REQUIRED。关键词：门 锁销 关闸 状态灯 碰撞。

既有门打开后的碰撞至少保留1.2s，与门叶让开同步。新关卡必须为关闭、开启中、已开、受阻提供一致的画面/碰撞/交互状态。门框应急灯双面可见，独立于探照灯；通路灯不等于通行许可，不能只用颜色表达状态。

当前普通openDoor主要是开启状态，不代表已实现可反复落闸、夹肢和机械锁销验证。救援货闸属于新增机关，必须显式实现并测试后再采用。关门成功不得只看按钮；录像确认要落在已经存在的物理门状态上。不得把主线工具关进不可再进入的捕食者仓。

依据：`docs/passage-door-standard.md`；`src/pod/content/expedition.ts`（openDoor）；`src/pod/view/deepsea/pod-expedition.ts`（openedAt、navigationSolids）。

## MET-016 威胁路线与暴露预算

状态：REQUIRED。关键词：怪物 威胁 躲避 安全区 摄影泊位。

每个强制静止曝光点必须有可解释的暴露预算或掩护；玩家前往诱导控制台不得必须先穿过待隔离目标。玩家路线、怪物路线、被救者路线分别画出并验证交叉时机。安全区不能只靠隐藏AI禁区成立，需门、距离、隔断或已验证的行为限制。

不把旧文档“8—14秒预警”强加给所有敌人：首关当前空间奔行者代码有3s初警、近距1.2s蓄势、7m/s追踪、12m/s冲刺、7s恢复等独立流程。五秒强制曝光不一定适合该近距攻击窗口，必须另设安全机位/中断机制，不能假设所有怪物都愿意等显影。

依据：`src/pod/view/deepsea/pod-expedition.ts`（tickRunner）；`docs/monster-ai.md`（历史通用猎手，非所有当前空间遭遇）。

## MET-017 资源与不可软锁

状态：IMPLEMENTED / REQUIRED。关键词：电量 氧气 补给 软锁 重拍。

当前单次曝光SHOT_POWER=0.06，分析ANALYZE_POWER=0.045，均为0—1电量比例，不是物理kWh。只算3次侦察+3次结果共6卷，曝光就要0.36；若6次都执行收费分析再加0.27，共0.63，尚未计灯光、驾驶、机械臂和失败。这是预算示例，不声称所有片都要重复付费分析。
