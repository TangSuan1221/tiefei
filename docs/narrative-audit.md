# 独立叙事管线审计

范围：`narrative-lab` 的独立剧情模型；不能将其状态图或文本试玩冒称主游戏五关已经实现。审计脚本为 `tools/narrative-audit.ts`。下方记录已执行模型检查、未验证范围及独立文本风险。

## 自动验收门槛

1. **结构与摄影闭环**：五章、每章三场，场景 ID 唯一。每场须有侦察、据片选择、物理结果、结果片、后续选择。结果片不可只有装饰性台词；跳过、未完成或过期证据不得获得相应知识。
2. **因果与角色知识**：事件使用有序时间及状态版本；录像保存曝光时快照。观看、读档或重复分析不能改写过去、重复收费或重发道具。角色仅可引用其已取得或明确接收的事实；主动说谎须与真实知识分开。关系变化必须能追溯到事件，不以一个信任阈值替代感染、拘束和通信等事实。
3. **可达与互斥**：每个公开选择与设计结局都有一条可执行见证轨迹。枚举有限离散状态，检查非终局状态是否至少存在通向结局或显式可恢复失败的路径。`自由/拘束/毁伤` 等互斥状态不同时成立；零、一、两名幸存者的对白和结局不出现幽灵角色。玩家自行无限等待不应被错误定义为图结构死锁。
4. **资源与能力**：记录每条边的前置资源、消耗、补给和不可逆影响。当前资源耗尽必须触发明确失败与恢复，不能留下无提示的无解界面。设备能力未取得前禁止调用；摄影和机械臂互斥。曝光五秒、显影十二秒分开测量；远端失败或一百秒延迟不能取消可靠本地证据或永久阻断下一次摄影。
5. **保存恢复**：曝光中、显影中、片已出未分析、选择已执行、结果待核验及终局分别往返保存。恢复后事实、知识、资源、历史和录像快照一致；无重复副作用。拒绝不兼容或损坏存档，独立试玩不得写正式游戏存档。
6. **反例与模型边界**：失败报告必须给初始状态、输入序列、预期与实得。遍历只证明所建有限模型内的性质；资源离散化、枚举上限及未建模行为必须列出。脚本不是表演质量与真实玩家理解力的证明。

## 六十分钟证据

- 六十分钟首先是设计预算，分列驾驶、操作、曝光、显影、阅读/思考、重试与可选内容；并行动作不得重复相加。字数除阅读速度不能证明游戏时长。
- 模型快进所得为模拟时间；浏览器真实等待所得为该次测试墙钟与游戏时间；二者分别标注。不得将一次瞬时状态遍历、脚本延时、强制空等或旧白盒两分钟通关外推为六十分钟实玩。
- 真人盲测需真实未看过剧情/路线的参与者、固定版本、统一任务与援助规则，记录是否完成、卡点、误解、提示次数及时间分布。失败和中途退出也必须报告，避免只统计通关者。
- 代理在不知道标签映射时比较匿名文本，仅称“代理盲化文本评审”。它不能冒称真人参与，也不能检验真实恐惧、疲劳、操作舒适度或市场质量。
