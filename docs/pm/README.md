## 状态规则

待核验：现有实现可能覆盖，但未验证。待办：明确需要制作。进行中：已分配实际执行。待验收：实现者提供交付与验证证据。验收通过：PM已按条件核验并记录证据。阻塞：注明原因、所需决策及可继续部分。

代码存在、构建通过、截图好看均不能单独证明可玩功能完成。设计稿完成与游戏实现完成分别记录。没有测试不能写通过；失败应回到进行中或阻塞，保留失败记录。

## 事件驱动核验节奏

1. 每批制作开始前：确定任务ID、责任角色、依赖与验收条件。
2. 每项交付后：实现者提交修改文件、复现步骤、测试结果及证据路径；主Agent通知PM复核。
3. 每个阶段完成前：检查正式游戏入口、端到端流程及旧功能回归。
4. 用户报告缺陷时：登记缺陷，关联任务；必要时撤销原验收结论，不覆盖历史。
5. 每轮交付用户前：同步台账，报告已验收、待验收、阻塞和下一步；不使用无依据的完成百分比。

这是一套制作期间的检查流程，不是已经启用的定时后台监控。本轮不创建定时任务，不自动调用付费视频接口，也不自动提交或上传仓库。
