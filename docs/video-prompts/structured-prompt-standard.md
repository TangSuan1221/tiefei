## VR-104 参考模板拆解与取舍

状态：REQUIRED。关键词：提示词结构 模板拆解 角色中心 等距 漫画 分段动作 物理反馈。

用户提供的城市潜行模板可复用的是“交代环境→固定角色→分段表演→明确摄影→补充氛围→限制偏移”的结构，不是其城市、人物或美术设定。

| 原模板部分 | 提炼出的要求 | 本项目应用 |
|---|---|---|
| 整体场景与风格 | 时间地点、空间锚点、材质、主光源、统一视觉语言 | 深海设施、前中后景、实际可见结构；不引入霓虹城市或漫画风 |
| 角色与装备 | 数量、位置、轮廓、衣着装备、固定辨识点 | 检索外观档案；只有出镜角色才展开；姓名不能替代外观 |
| 时间与节奏 | 起始状态、每段行为、停顿、先后关系 | 按所选5秒或10秒配置安排，不复制15秒时间轴 |
| 摄影与取景 | 视角、景别、焦距/视场、跟随方式、画幅边界 | 沿用固定潜艇摄像头或已授权移动探头；不默认等距俯视、跟拍或变焦 |
| 细节与氛围 | 环境运动、材质反光、动作产生的反馈、声音 | 水流、海雪、接触扬泥、有限灯光；声音与可见信息分开 |
| 约束 | 角色一致、结构一致、碰撞、可读性、禁止新增 | 压缩为与本镜头相关的条款，保留正典和事实边界 |

原模板的冲突需要在组装前解决，不能原样堆入：

- “缓慢谨慎”与“极高爆发力”不能全程同时成立。每一时间段只能有明确的动作速度；确有突发动作时单独指定起止、触发与停止后的反馈。本项目不得因此新增袭击。
- “始终三人在画面内”与“消失在黑暗中”需明确是细节变暗、被遮挡还是离开画幅，不能同时要求主体全身持续清晰和完全不可见。
- “固定高度角度、等距平移”与“几个场景由运镜切换”不能默认兼容。本项目一卷连续现场录像不跨场景剪切；移动探头只沿已经授权的实际路径移动。
- “严禁播放分镜”解释为生成连续运动，不是把分镜卡、字幕或静态图片依次播放；不解释成禁止使用时间段描述。
- “必须保留”必须写明保留对象；“与参考图一致”必须有实际提供的参考图。没有图时，不引用示例文件名或声称已锁定参考。
- “符合物理”须落到本段动作：脚/手的接触点、绕障路线、关节方向、惯性和接触反馈。水下动作遵循介质与浮力条件，不能机械套用地面步行或无条件下坠。

## VR-105 八段结构与最小信息

状态：REQUIRED。关键词：新规范 结构 角色装备 动作序列 摄像机 结束状态。

最终模型正文沿用英文；以下中文为编写规范。元数据保留镜头ID、来源、剧情原文、状态、中文说明及所用参考文件，不拼进模型正文。每条独立使用，不写“同上”“原来的怪物”或仅有姓名。

1. **主体与镜头契约（SUBJECT / CONTRACT）**：第一句写谁、在哪里、正在做什么；标明主体数量、片长、画幅、连续镜头。侦察拍当时现场，结果片从已发生的结果开始；不补演此前操作。
2. **环境与风格（SETTING / STYLE）**：地点与介质、前中后景、2—4个空间锚点、通路与遮挡、主光源和既有美术风格。只描述当前视锥能看到的内容；未知电源、身份或心理不写成画面。首帧参考图存在时优先锁定它，不任意左右翻转、增加开口。
3. **角色与装备（SUBJECT DESIGN）**：按出镜主体分别写位置、尺度/比例、身体轮廓、衣着材质、装备及2—3个辨识点；多人用固定位置/名称区分，不交换装备。怪物写具体形态与运动方式，不解释生物来源。遮挡处不强求露脸、眼神或全身细节。
4. **动作序列（TIMING）**：每段写“时间→主体→动作/方向→接触或环境反馈→停下时的位置”。同时行动需明确谁动谁停；停顿有可见姿态，不用“紧张”“观察”替代动作。5秒通常1—2个动作段，10秒通常2—3段；段落覆盖全片且不重叠矛盾，最后保留可判读的稳定结果。稳定结果片允许全程只呈现细微呼吸、肢体调整和颗粒运动，不为填时间新增事件。
5. **摄影与取景（CAMERA）**：机位来源、朝向/高度关系、景别、景深/对焦对象、允许的运动及不可见区域。固定摄像头写明不平移、不推拉、不绕行；移动探头明确谁持有、如何移动、是否仍受同一视线遮挡约束。角色移动不等于相机必须跟随。正文不得同时要求固定镜头和重新构图。
6. **细节、光影与声音（LIGHT / ATMOSPHERE / AUDIO）**：保留少量对判读有用的材质和水体细节。光源位置与阴影方向稳定；硬阴影仅在已有定向光允许时采用，不能牺牲证据可读性。声纳无可见光圈；远声不生成未知生物；不支持音频时省略声音，不能改成字幕或可见对象。
7. **结束状态（END STATE）**：明确结尾人物、生物、门、道具的位置与状态，以及哪些事实仍未知。必须与曝光结果一致，不追加落闸、获救、伤亡、治愈、逃脱或会合。
8. **连续性与禁止项（CONTINUITY / LIMITS）**：保持主体数量、外形、装备、空间和风格；动作速度与位移一致，接触有对应反馈，不穿模、不瞬移、不新增人/物/剧情。只列本镜头相关限制，并继承既有必要禁项；不反复抄写风格形容词。

兼容已有拼装：上述为逻辑字段，不要求强行改变VR-001前缀→PT正文→后缀的次序。共用风格/禁止项由后缀表达一次；片长、画幅、机位已在前缀写明时正文不重复。叙事组装器现有subject、profiles、space、camera、light、beats、audio、endState、style分别对应以上字段；连续性与动作反馈可写入相关字段，无需新增八套重复内容。

## VR-106 长度预算与输出检查

状态：REQUIRED / IMPLEMENTED / GAP。关键词：字符上限 2200 3600 压缩 预算 校验。

保留两个既有配置：主游戏历史PT设计模板5秒、最终正文≤2200字符；叙事测试模板10秒、最终正文≤3600字符。它们是项目拼装限制，不冒称服务商通用限制。不使用参考样例的15秒，不提高上限。计数沿用JavaScript字符串length，计入英文空格、标点、标题、换行、前后缀和展开后的外观；不是中文字数、英文单词数或token数。元数据与不送模型的中文说明不计入正文。

| 逻辑段 | 2200配置建议预算 | 3600配置建议预算 |
|---|---:|---:|
| 主体与契约 | 100 | 140 |
| 环境与风格 | 260 | 450 |
| 角色与装备 | 420 | 700 |
| 动作序列 | 560 | 900 |
| 摄影取景 | 260 | 450 |
| 光影、氛围、声音 | 160 | 240 |
| 结束状态 | 120 | 220 |
| 连续性与禁止项 | 180 | 300 |
| 标题、换行与余量 | 140 | 200 |
| **最终总上限** | **2200** | **3600** |

分段预算可互借，不是各字段硬限额。旧PT固定后缀较长，先计固定前后缀，再用剩余额度填写镜头正文，不能按表再叠加一份后缀。多角色也必须满足总上限。

超限处理顺序：去掉制作说明与复述→合并重复机位/风格/禁项→删装饰性修饰、次要氛围与非必要音效→减少非关键动作。始终保留主体识别、关键空间/遮挡、合法动作、可见结果与事实边界。不截断字符串、不拆成会丢上下文的半条prompt、不为缩短而改剧情；仍超限则拒绝导出并标GAP，回到镜头设计。

可复用编写骨架（占位符必须在导出前完整替换）：

```text
SUBJECT: [Visible subject count, location and present action]. [Duration], [aspect ratio], one continuous shot.
SETTING: [Spatial anchors, route, occlusion, established visual style].
DESIGN: [Each visible subject: position, silhouette, materials, equipment, identity anchors].
TIMING: [Start-end: subject, motion, direction, contact response, pause/end pose].
CAMERA: [Source, angle, framing, focus and permitted movement].
LIGHT/AUDIO: [Practical light, readable detail, restrained environmental motion; supported sound only].
END: [Exact final positions and states; unresolved information stays unknown].
LIMITS: [Appearance and geometry continuity; physical contact; no added entities, cuts, UI or invented outcomes].
```

导出前逐项检查：参考图确实存在；出镜人物有档案；数量与位置一致；时间覆盖正确；慢动作与爆发段不冲突；位移/障碍/反馈明确；机位指令单一；不把声音、隐藏知识或推断画成事实；关键结果可持续判读；无残留占位符；完整正文不超限。

IMPLEMENTED：现有拼装器执行总长度与未解析内容检查，本地RAG检索此规范。REQUIRED：新写与重写条目按八段组织并作语义审查。GAP：本次为规范整合，不代表全部存量条目已重写或物理、时间、风格冲突已有自动语义检测；不改变保存中的旧片快照，不调用视频生成接口。

## VR-110 怪物的深海克系恐怖表达

状态：REQUIRED / 主游戏首关与第二关文字档案IMPLEMENTED / 参考帧去生物模型IMPLEMENTED / 生成效果GAP（未重新生成验收）。关键词：怪物 深海 克系 恐怖 Lovecraftian abyssal horror 外观 陆地生物 爬行 视频生成 不用模型 video-creatures。

用户明确：怪物是恐怖的深海克系生物。出镜怪物的描述必须明确abyssal / Lovecraftian horror，并用可见形态落实，不能只写“怪物”“苍白生物”，也不能把它渲染成可爱海洋动物、吉祥物或普通穿服装的人。

用户最新澄清：海底生物多样，不只有一种怪物；长肢、人形、苍白皮肤、低伏姿态均不是通用要求。共同要求是深海克系恐怖气质，外形、尺度、材质和运动方式必须逐物种定义。不得把港区生物档案作为其他生物的默认值。

按本卷曝光中实际出现的生物ID检索各自档案和参考截图，分别描述整体体型与尺度、身体组织方式、表面材质、感知结构、推进或附着方式、特有运动节奏。人形、软体、甲壳、多节、漂浮或群体只是可区分的形态类别示例，不表示这些物种已在项目中设定或实现。具体结构只能来自该生物已有档案；没有手就不写手指，没有脸就不写表情，不把触腕、背棘、长肢或发光眼普遍化。

同一卷出现多种生物时，分别锁定各自数量、位置、轮廓和动作，禁止互换特征或融合成一种怪物。缺少对应生物档案时标GAP，不套用港区档案，也不依据“恐怖”一词随机造型。未见实体只保留声音或痕迹，不为展示多样性额外添加生物。

2026-10-12用户指出：生成视频中的怪物全部像陆地生物。根因是首关运行时手写外观只有“低长身体、带关节的爬行四肢、肉质皮肤”且无任何深海词，并只否定鲨鱼/海洋动物；第二关只传类型代号并要求“照首帧模型”。用户同时明确：**怪物全部由视频生成，不使用3D模型**。因此：

- 曝光参考帧不渲染任何生物模型（首关一直隐藏；第二关快门首帧传空生物列表，仅探头远端录像保留），请求一律 `generatedMonsters:true`，外观只来自文字档案。
- 唯一运行时档案：`src/pod/content/video-creatures.ts` 的 `VIDEO_CREATURES`（harbor / lumen / shade / blind / swarm）。叙事库 `src/narrative-lab/prompt-library.json` 的 harbor 档案须与之同义。
- 每条非普通生物档案写可见深海解剖（半透明或受压软化组织、鳍膜、鳃裂、侧线孔、管状眼、退化眼、发光点等，按物种取用）和水中运动方式（悬浮、滑行、摆尾、攀附），明确不站立、不行走、不爬行。禁止“爬行四肢”“四肢着地”“低长身体”等陆地描述。
- 通用约束（`slotPrompt`）正面要求 abyssal Lovecraftian 深海生物，并否定陆地动物、爬行类、恐龙、哺乳类等；不再只否定鲨鱼和海洋动物。`tools/video-policy-check.ts` 检查上述措辞。

港区怪物外观以用户第一章怪物参考图 `public/assets/harbor/references/harbor-creature.png` 为准：多个类人头部融合为一个主体，暗红组织、垂落有机条带与工业软管、金属接头交织；多视图是同一个体。取消旧单头长臂、蹼指、背鳍与鱼尾描述。环境截图只约束场景、镜头及遮挡，附加怪物图约束外观；数量、尺度和动作服从当前摄影事实，不解释来源与身份。

第二关生物按 `docs/level-02-living-deck-design.md` 设定写成文字：趋光者为长袍人形上身、皮下淡色发光点、腰下化为水母缘般拖曳组织、面朝光源（视频配色禁青，不写“淡青”）；避光鳗约5米、半透明带状体、背腹连续鳍膜、鳃裂、管状眼，强光下盘成团；盲猎者约3米、巨大钝头无眼、下颌外露长牙、体侧侧线孔、背棘冠、肉质胸鳍与高尾鳍；鱼群为普通玻璃鱼与端足虫。

恐怖通过轮廓、尺度参照、克制运动、局部照明和遮挡建立，不靠新增血腥、随机跳吓或把全部画面压黑。重要外形与证据仍需可读。参考截图只约束环境、人物、机位与遮挡；生物不出现在参考帧中，形态以文字档案为准，不允许模型擅自换物种。

只对镜头明确可见的生物注入外观；仅有声响、影子、痕迹时不补出实体。Panacea无攻击性的正典、首关人物身份保密和未知生物来源继续有效；克系是视觉与氛围要求，不是捕食病毒、邪教神像或怪物必然攻击的剧情解释。沿用原字符限制，替换泛化形容而非无限追加修饰。

## VR-111 固定潜艇摄像头：全片零运镜

状态：IMPLEMENTED / REQUIRED / 生成效果GAP。关键词：固定摄像头 零运镜 禁止漂移 禁止跟拍 camera lock。

2026-10-12用户明确：摄像头固定在潜艇上，生成录像的相机位置始终固定。整卷锁定触发截图的相机位置、旋转、画幅、焦距和视场。禁止平移、推拉、摇摄、俯仰、滚转、环绕、跟拍、变焦、重新构图、漂移、手持抖动、受击震动和镜头切换。生物移出画幅也不追随；允许生物、水流和颗粒运动，不允许静态结构产生相机运动造成的位移或视差。电影质感只通过既定光照、材质和主体表演实现。

## VR-116 剧情视频中文字幕与原声

状态：IMPLEMENTED / REQUIRED / GAP。关键词：字幕 中文 字体 字号 位置 原声 声音 静音 subtitles audio SPEECH dialogue。

2026-10-28 用户要求：所有剧情视频都配中文字幕，先定字体、语言、字号、位置并统一写入提示词规范；游戏视频不得再屏蔽声音。本条覆盖此前“本作声音全部WebAudio合成、片子不许出声”的实现约定。

**字幕由游戏叠加，不由视频模型烧录。** 模型画中文字形不可靠，字幕又必须与台词逐字一致、能随静音和回放暂停。提示词正文继续保留禁止生成字幕/文字条款（第一关 `MESSAGE: No subtitles…`、第二关 `No generated subtitles…`、第三关后缀 `No captions, subtitles…`）。已上线条目的英文正文不为本规范改写：提示词变化会改变缓存键并重新计费。

**字幕原文与台词同源，不另写一份：**

| 视频 | 模型是否配音 | 字幕原文 |
|---|---|---|
| 第一关任务自拍 L1-E** | 是，`SPEECH:` 行 | `HARBOR_TASKS[id].speech` |
| 第二关任务自拍 L2-S** | 是，`SPEECH:` 行 | `LIVING_TASKS[id].speech`，`{code}` 替换为本局编号 |
| 第三关艾里亚斯录像 L3-E** | 否（VR-301：台词不进提示词） | 剧情状态机选中表演的 `dialogue`，每行“说话人：内容” |
| 玩家摄影、结果片、环境片 | 无台词 | 不加字幕；环境声不改写成字幕（VR-105第6项） |

新增带台词的镜头必须在同一数据条目里给出台词（SPEECH或dialogue），由 `src/pod/content/video-subtitles.ts` 生成字幕；不得在提示词外手写另一版字幕，也不得让字幕承载画面里没有、台词里没说的信息。

**版式（唯一来源：`VIDEO_SUBTITLE_STYLE`）：**

| 项 | 规定 |
|---|---|
| 语言 | 简体中文（zh-CN），台词原文直出，不翻译、不意译 |
| 字体 | 全作中文黑体栈 `SANS_CJK`（PingFang SC / Microsoft YaHei / Noto Sans SC / Source Han Sans SC），正文字重500；说话人名字重600 |
| 字号 | 录像画面高 × 5.8%，夹在20—34终端逻辑像素（分析台1024×720坐标）；放大窗968×369约21px，小窗646×207取下限20px |
| 行距与行数 | 行高1.4倍字号；每条最多2行，按画面宽86%实测断行，遵守避头尾 |
| 位置 | 录像画面（等比放大时为实际画面矩形，不含黑边）底部居中，底带下沿距画面底边6%画面高；不遮挡顶部取景器读数 |
| 颜色 | 正文骨白 #ECEBDD；说话人名琥珀 #F0BF78，后接全角冒号“：”；黑色柔和阴影；半透明深色底带 rgba(4,10,12,.72)，宽度随文字 |
| 切条 | 按句末标点（。！？…）分条；单条超过36字（2行×18字）时在逗号、顿号、分号处再切；去掉条尾句号和逗号，保留问号、叹号、省略号 |
| 时间 | 无服务商逐字时间轴。播放列表载入后检测原声人声区间（50ms窗口，阈值−35dBFS或峰值12%），字幕按字数比例铺在人声区间内；无音轨或未分析完时铺满片长（首留0.4秒、尾留0.3秒）；单条不短于1.2秒（总时长不足时均分）。多段播放列表按合计时间轴连续计时 |

**原声：** 剧情视频保留模型生成的原声，只跟随全局静音开关（GM“静音”）；静音时字幕照常显示。只有正在画上屏的那一卷出声，离屏300ms内暂停，避免离开分析台后后台循环出声。浏览器拦截有声自动播放时先静音播放，下一次点击或按键后恢复声音。

实现：`src/pod/content/video-subtitles.ts`（版式常量、切条、时间轴）、`src/pod/view/video-subtitles.ts`（叠加绘制）、`src/pod/view/footage.ts`（原声、离屏暂停、人声区间、分析台回放叠字幕）；各关播放器在登记录像时写入 `TapeRecord.subtitles`，旧存档按任务ID从同一台词表还原。检查：`npx tsx tools/video-subtitle-check.ts`（台词与字幕逐字一致、每条≤2行、时间不越界不重叠、录像未被硬静音、提示词保留禁止烧录字幕条款）。

GAP：时间轴是人声区间内的字数比例估计，不是逐字对齐，语速变化或长停顿处字幕可能略早或略晚；未用真实生成录像在游戏内逐卷审听审看。第三关VR-301所述“游戏配语音”未实现：当前第三关录像只有模型生成的环境原声与字幕，没有艾里亚斯语音。原声音量未接入游戏音量总线，只有开/关。
