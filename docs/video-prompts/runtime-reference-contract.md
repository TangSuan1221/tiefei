# 运行时视频参考截图契约

## VR-107 每次生成必须携带触发现场截图

状态：REQUIRED / 部分IMPLEMENTED / GAP。关键词：实际截图 上传 first_frame 玩家位置 艾里亚斯坐标 触发点位 视频类型。

用户最新要求：每次向视频模型提交生成任务，必须同时提交剧情触发点位的实际渲染截图和提示词。参考截图不是可选槽位；仅有提示词不能提交。此要求覆盖此前规范中允许无图文生测试作为可提交视频任务的条款。离线提示词预览仍允许，但必须标记“缺少实际参考截图，不可提交”。

| videoType | 截图位置与机位 | 禁止替代 |
|---|---|---|
| player-capture：玩家拍摄 | 触发/曝光时玩家实际位置，使用其当时摄像机朝向、倍率、视场与光照 | 不使用目标物坐标、艾里亚斯机位或稍后移动后的玩家视角 |
| player-action：玩家行动引发的录像 | 该视频触发时玩家实际位置和摄像机状态；触发点是行动结束还是开始由剧情事件显式指定 | 不因行动对象是艾里亚斯就改用他的机位，不把执行前截图当成执行后结果 |
| elias-story：艾里亚斯自身剧情 | 以触发时艾里亚斯的实际世界坐标为锚点，使用该节点登记的艾里亚斯场景摄像机截取他的现场 | 不使用玩家位置、不读取艾里亚斯旧坐标、不回退到潜艇首帧 |

视频类型由剧情节点显式配置，不通过提示词中是否出现“艾里亚斯”猜测。艾里亚斯坐标是场景机位锚点，不等于把相机塞入身体：节点必须指定眼位/局部偏移、朝向、视场及锚点坐标系。第一人称使用其眼位且不强行拍到全身；需要第三人称出镜时登记围绕其实际坐标的合法机位和偏移，校验无遮挡，不默认全知俯拍。缺少机位即GAP，不自动发明位置。

玩家摄像头仍遵守MET-006，不能因为增加NPC剧情机位而获得透墙、瞬移或远端摄影能力。艾里亚斯机位只用于对应剧情视频，不自动授予玩家远端事实；是否收到/看过录像仍由原剧情链裁决。

## VR-108 运行时读取与提交顺序

状态：REQUIRED / GAP。关键词：配置 JSON 快照 字段 cache 重试 截图失败。

机器可读配置：`src/pod/content/video-reference-policy.json`。运行时应按routes选择截图来源，未知类型拒绝提交；该配置已落盘，不代表所有调用方已经接线。

固定流程：

1. 剧情触发，锁定triggerId、sceneId、epoch、capturedAt、videoType及人物/门/生物/光照状态。
2. 按类型从同一触发快照读取玩家或艾里亚斯坐标，解析对应摄像机。异步渲染时保留这份场景状态，不能先等待再读取已经变化的世界。
3. 从真实场景渲染PNG参考图，记录anchorEntityId、anchorPosition、cameraPosition、cameraQuaternion、verticalFov、aspectRatio、lightingState、imageHash。只渲染该机位合法可见内容，不截桌面、编辑器、文字分镜卡或其他标签页；不叠加HUD，不移动真实玩家来凑NPC机位。卸载或不存在的NPC场景须正确加载到冻结状态，无法做到则停止。
4. 提示词从同一快照组装，说明当前是玩家现场机位或艾里亚斯现场机位，明确主体/遮挡/首帧状态与允许动作。必须要求保持所附实际截图的构图、建筑和光照，不再出现“如果提供参考图”。坐标及哈希留在元数据；无必要不占模型正文字数。
5. 校验图像非空、可解码且尺寸有效，校验类型/人物/机位/场景/epoch与触发一致，再将PNG通过现有供应商适配器的first_frame字段，与prompt同一次提交。正文长度按最终发送内容计算，包含网络层追加的首帧指令；不因加参考图而提高2200/3600字符上限。
6. 保存此次图像、机位元数据、提示词与任务关联。审核重试使用同一锁定截图，不在返片时重拍；缓存必须区分类型、触发快照、机位、图像与提示词。命中完全相同的已有结果属于播放缓存，不是新的生成请求。

任何截图缺失、机位未配置、NPC不存在、渲染失败、状态不一致、图片格式错误或供应商不支持图像输入，均拒绝新生成并显示明确失败原因；不回退为纯文字生成，不换成玩家截图、不用旧图或概念图顶替。参考图中的旧外观与提示词档案冲突时先修复资产/档案，不让模型自行换人。
