## 1. Vitals 模型

### 1.1 八项状态与演化

八项 Vitals 逐呼吸演化，推进单位是**呼吸数**而非帧或秒。
`advance(dt, ctx)` 的 `dt` 是本次动作的实际呼吸成本，所有变化率都乘 `dt` 积分。
这保证了"花 12 个呼吸撬一扇门"和"走 12 步"在生理上等价——
玩家花掉的是同一种东西，游戏不需要两套时间。

演化按固定顺序分六步：状态效果 tick → 呼吸 → 体温 → 躯体 → 心智 → 环境危害。
顺序不是随意的：状态效果先于一切，因为它们代表"上一个呼吸留下的后果"；
心智放在躯体之后，因为恐惧要读到本呼吸最新的 CO2 和体温。

### 1.2 派生属性

```
derived(stat) = clamp( (baseline + Σ add) × Π mul × intrinsic(stat) , lo, hi )
```

先 add 后 mul 是硬性顺序：反过来的话，一个 +2 的 add 会被一个 ×1.5 的 mul 放大成 +3，
状态效果之间就产生了设计时无法预料的耦合。`intrinsic` 是不来自任何状态效果、
而是 Vitals 本身的直接后果的那一部分（见下）。

结果按 `(stat, 状态版本)` 缓存，因为单个呼吸内 `derived('breathCost')` 会被查询十几次。

### 1.3 breathCost —— GDD §4.1 的四个修正项

```
breathCost = (1 + fear/100 × 0.55)
           × (1 + co2/100 × 0.60)
           × (1 + trauma/180)
           × (coreTemp < 36 ? 1 + (36 - coreTemp) × 0.08 : 1)
```

乘法而非加法，因为这四项在现实里是复合的：
一个恐慌的、高碳酸血症的、失血的、体温 33 度的人，其代谢惩罚不是四份相加，
而是彼此放大。乘法同时制造了本作最重要的死亡螺旋——
四项各自只贵 20%，合起来就是贵一倍，玩家的氧气预算会在他还没意识到之前崩掉。

### 1.4 屏息 —— 本作最重要的微观决策

| 操作 | 效果 |
| --- | --- |
| `holdBreath()` | 氧气冻结；CO2 +4/呼吸（GDD 明文），按恐惧 ×1.45 上限、体力消耗 ×1.8 上限放大 |
| `release()` | 主动吐气：立刻清 22 CO2，噪音只有大喘气的 1/6 |
| `gasp()` | CO2 ≥ 80 强制触发：清 35 CO2、噪音 25、恐惧 +18、额外烧 6 氧 |

设计上必须先看清一件事：**屏息在氧气账面上是净亏的**。
憋住 1 个呼吸省 1 点氧，代价是约 5 点 CO2，而在品质 0.5 的空气里清掉这 5 点
需要约 1.5 个呼吸的正常换气——净亏约 25%。

所以屏息不能是"省氧手段"，它必须换来别的东西，否则它只是一个陷阱选项。
它换来三样：

1. **安静**：屏息时 `noiseEmission` 内禀降到极低（做成内禀项而非状态效果，
   因为存档往返时一个残留的"永久静音"幽灵状态是灾难性的 bug）。
2. **可穿越没顶舱室**：`swim` 强制屏息，CO2 太高时 `holdBreath()` 直接拒绝，
   于是你在水里呼吸——这就是溺毙。
3. **压迫感减半**：屏息时环境 `presence` 对恐惧与 SAN 的输入 ×0.55。
   一个静止、无声、连呼吸都收起来的人确实更不容易被注意到。

第 3 条是模拟器逼出来的：没有它时"屏息潜行型"存活率 7.5%，62.7% 死于窒息——
它是四个原型里唯一不可行的那个。补上之后升到 47.5%。

**过度换气**（`fx.hyperventilation`）是屏息循环缺失的另一半。
被动呼吸的净清除率约 0.9/呼吸，而屏息是 +4/呼吸，比例 1:4.4——
没有一个主动"还债"的动作，屏息就是一道单向棘轮。
加入它之前，屏息流 38.5% 的 run 直接死于 CO2 中毒。
它也不白给：照搬自由潜水的事实，它压低的是**警报**而不是氧储量，
所以它同时扣 `lucidity`——被压低的不只是血气，还有你对自己状态的判断力。

### 1.5 阈值与死亡

八项各有四档阈值，穿越时 emit `vitals-threshold`。
四档是人能记住的上限；玩家需要的是分级的坏消息，不是连续的数字焦虑。
`oxygen` / `san` 的刻度按**占上限的百分比**算，因为 `oxygenMax` 会被装备改变。

九种 `DeathCause` 全部实现。其中"自戕"不是 SAN 归零的惩罚
（GDD §4.2 明确 SAN 归零不死），而是恐慌 ≥85、SAN ≤12、CO2 ≥40 三者同时成立时，
角色自己摘下面罩。三重门槛保证它罕见且可预防。

### 1.6 perceived()

HUD 只读 `perceived()`，永远不读真值。它把真实 Vitals 交给 `VeracityEngine.number()`，
再叠加隐藏状态的定向偏置（例如 `fx.hidden.gauge-lie` 让氧气表偏乐观 14%+6）。
同一呼吸内重复查询必定返回同一结果——不一致的读数会让玩家一眼看穿。

## 2. 状态效果库

共 **66** 个，全部带中文名与临床风格描述。

| 类别 | 数量 | 内容 |
| --- | --- | --- |
| 物理类 | 21 | 肋骨骨裂、长骨骨折、持续失血、低温症一度/三度、冻伤、减压病、耳膜穿孔、肺水肿、缺氧性脑损伤、烧伤、撕裂伤、挤压伤、呛水、二氧化碳麻醉、力竭、脱水、耳鸣、氮醉、低血糖、过度换气 |
| 精神类 | 14 | 恐慌发作、解离、偏执、既视感、命名性失语、幽闭恐惧发作、现实解体、过度警觉、幸存者罪疚、幻听、紧张性木僵、情感麻木、强迫计数、尾随 |
| 感染类 | 8 | 接触一至五期（盐斑→共振→灰鳃→合唱→圣化）、强迫聆听、肉之印、替换 |
| 仪式类 | 8 | 六种 Stigma（缄默/聆听/溺者/铁/肉/叛教）+ 现实锚、尸油涂层 |
| 增益类 | 9 | 肾上腺素、镇静剂、纯氧、保温层、镇痛剂、提神剂、广谱抗生素、碱石灰回路、静息 |
| 隐藏类 | 9 | 表盘偏差、回声负债、倒数、它记得你、借来的一口气、已调谐等 |

其中 41 个是永久状态（`duration < 0`），52 个带逐呼吸 tick，61 个带派生修正。
（类别按 tag 优先级归一，故各行相加等于 66；隐藏状态中有 3 个同时带物理/精神 tag。）

**感染五期**是一条完整的浮士德曲线。前三期纯粹是惩罚；
第四期「合唱」开始给正收益（`breathCost ×0.88`，因为你开始不那么需要呼吸了）；
第五期「圣化」给出全作最强的机械收益——`breathCost ×0.55`、声呐半径 +2.5、
氧气每呼吸**回升** 0.62——代价是它同时是一个 `terminal` 标签的死亡倒计时。
这是本作对"变强"这件事的态度：最强的 build 是你正在停止做人。

**隐藏状态**是心灵恐怖的机械化：它们真实生效但玩家在 UI 上看不见。
`fx.hidden.oxygen-leak` 让储量以表盘之外的速率减少；
`fx.hidden.gauge-lie` 让表盘本身偏乐观。玩家只会感觉到"这次氧气不太够"，
而这正是我们要的——把不安做成机制，而不是做成音效。

## 3. Veracity Layer

### 3.1 污染度模型

```
target = clamp01( ( (1 - san/sanMax)^1.35 × 0.62
                  + infection/100      × 0.22
                  + depthNorm         × 0.14
                  + listening/6       × 0.18 ) × resist )

resist = 1/(1 + lucidityPermanent × 0.06) × 1/(1 + lucidityFromEffects × 0.018)

corruption = damp(corruption, target, λ=0.09, dt)
```

三个决定：

- **SAN 项取 1.35 次幂**：前半程掉 SAN 几乎无感，后半程雪崩。
  线性的话玩家会在中段就察觉到世界在变形，而心理恐怖需要的是"回头才发现"。
- **两种 lucidity 抗性分开算**，永久的（debunk 攒的）比临时的（现实锚给的）强三倍多。
  否则一个道具就能把全作招牌机制关掉。
- **必须平滑**（`damp` 而非直接赋值）。逐帧跳变会让 HUD 抖成噪点，
  玩家立刻发现"游戏在搞鬼"。缓慢的漂移才会被误认为是自己的问题。

层级下界 `[0.15, 0.30, 0.50, 0.70, 0.88]` 对应 GDD §5 的 L0–L5，未做改动。

### 3.2 文本污染

六种独立算法，按层级提升变异密度（每 12 字的期望变异次数：
L0 = 0、L1 = 0.35、L2 = 0.8、L3 = 1.6、L4 = 2.6、L5 = 3.4）：

1. **形近字替换** — 日→曰、未→末、土→士、己→已、戊→戌…（`lexicon.ts` 的 `GLYPH_MAP`）
2. **近义错义词替换** — 换成意思相近但关键处不同的词，语法完全通顺
3. **句子重复** — 整句复述，中间插入口吃式连接词
4. **闯入句** — 插入一句不属于这个文本的话
5. **否定反转** — 删掉或添加否定词，把意思翻过来
6. **人称替换** — 第二人称换成第一人称（"你听见"→"我听见"）

L5 共鸣层额外启用**真假反转**：`resonant` 为真时，清白的文本反而被标记为可疑，
而真正被污染的文本读起来最干净。这一层的设计目的是让"识破"这个动作本身失效。

### 3.3 数值污染

L1 是 GDD 明文的 ±2 绝对漂移，L2 起改为百分比（4%/9%/16%/28%）。
漂移**按 (数值 ID, 帧 epoch) 确定性生成**：同一帧内重复查询同一数值返回同一结果。
这是硬性要求——不一致的读数是最容易被识破的破绽。

氧气表带 `oxygenOptimism = 0.62` 的定向偏置：它撒谎的方向偏乐观。
撒谎的方向本身就是叙事——它想让你留下。

### 3.4 Lie 与 Tell

全部 10 种 `FabricationKind` 均已实现，各自带层级门槛、基础触发率与冷却：

| 类型 | 最低层 | 冷却（呼吸） |
| --- | --- | --- |
| footstep / hud-drift | L1 | 14 / 8 |
| voice / fake-item / mirrored-room | L2 | 26 / 40 / 150 |
| false-memory / impossible-geometry | L3 | 120 / 110 |
| save-prompt / fake-npc / fake-door | L4 | 220 / 180 / 90 |

**不存在没有 tell 的谎言**——这是 GDD §5 立下的契约，在 `birth()` 里机械地强制：
每条 Lie 生成时必定从该类型的 Tell 库里抽一个具体可观察的破绽。
`debunk()` 给 SAN +8、永久 lucidity +1，并立刻把 corruption 拉低 0.04，
让玩家马上"看见世界变清楚了一点"——正反馈必须即时。

`setBias(kind, multiplier)` 是留给导演的个性化恐吓接口（见下）。

## 4. 导演 AI

### 4.1 三条曲线

- **tension（张力）**：当下有多难受。七项加权，权重和为 1，故天然落在 0..1。
  它读**真值**而不是 `perceived()`——否则 Veracity Layer 会把导演自己也骗了。
- **intensity（强度）**：玩家被压了**多久**的积分，只在张力高于地板线 0.24 时增长。
- **phase**：`build → sustain → relief` 状态机。

强度在喘息相里**完全停止积分**。这不是优化而是修正一个 bug：
积分速度 `(tension - 0.24) × 0.06` 在典型张力 0.45 下约 0.0126/呼吸，
而 `reliefDrain` 只有 0.012/呼吸——净值为正，导演一旦进入喘息相就再也出不来，
一整局只能拿到 1 次喘息室。修正后每局稳定 1.5–1.8 次。

喘息相是 AAA 节奏感的关键。没有它，游戏会变成无差别的高压噪音，
而玩家对持续高压的反应不是更害怕，是麻木。

### 4.2 行为画像

`PlayerProfile` 用半衰期衰减统计五项：aggression / thoroughness / sonarReliance /
piety / panicResponse。它们的用途是**个性化**而不是难度调节：

- 重度依赖声呐的玩家 → 提高 `footstep`/`mirrored-room` 伪造偏置，让回波开始说谎
- 潜行型玩家 → 怪物池向 `stealthy` 倾斜（莽夫就给他一个能正面撞上的东西）
- 高 piety → 仪式相关的伪造更频繁
- panicResponse 高 → 更多假脚步声，因为他会跑

### 4.3 严禁作弊

导演只能产出 `DirectorOrder`，没有任何直接改写世界状态的能力。
生成点必须满足 `hops >= minSpawnHops`（不能在玩家脸上刷怪），
且权重随距离理想值的偏差衰减（也不能刷到地图另一端去，那样玩家永远碰不到它）。
生成还要花 credits，credits 按呼吸数线性积累并设上限——
导演的"预算"是显式的，不能凭空变出威胁。

生成概率与张力正相关、与**强度反相关**：已经被压了很久的玩家不该再挨一刀。

## 5. 平衡模拟器

`npx tsx tools/balance-sim.ts [--runs=2400] [--seed=20260915]`

模拟器自带一个抽象世界（实现 `WorldSystem`），不 import `src/world`——
那是并行开发中的目录，依赖它会让调参循环随时被别人的半成品打断。
抽象世界只保留对生理系统有意义的维度：噪音、淹水、压强、空气品质、注视感。
平衡数据关心的是资源流，不是走廊形状。

四种策略原型：保守搜刮型 / 激进冲刺型 / 声呐依赖型 / 屏息潜行型。
它们的差异不只是权重，还包括**行为纪律**：
例如"会不会停下来把气喘匀"（`ventDiscipline`）——
冲刺流并非不懂过度换气，只是没那个耐心，给它 55% 的执行率。

| 保守搜刮型 | 3.1 | 18.0 | 35.7 | 49.5 | 63.1 | 0.607 |
| 激进冲刺型 | 25.9 | 44.0 | 63.5 | 74.0 | 80.7 | 0.348 |
| 声呐依赖型 | 0.0 | 9.8 | 26.1 | 43.5 | 59.4 | 0.596 |
| 屏息潜行型 | 0.0 | 17.9 | 35.9 | 53.4 | 65.7 | 0.567 |

冲刺流的 SAN 中位数明显高于其他三者（63.5 对 26–36）。
这**不是** bug：跑得快的人看到的东西少，污染度只有 0.348。
它的代价写在死因表里——它是四个原型中存活率最低的那个。
"你想看多少真相"和"你想活多久"在这里是一组显式的交换。

### 5.4 结果的稳健性

换主种子（`--seed=77771`）重跑 2400 run，诊断同样全绿，
四项存活率与死因分布的偏移均在 3pp 以内。
模拟器完全确定性（无 `Math.random()`），同种子逐位可复现。

## 6. 关键调参决策

按影响从大到小排列。每一条都是模拟器打脸之后的修正，不是拍脑袋。

### 6.1 氧气上限 900 → 680

`startMax` 原值是照着 GDD 的"约 15 分钟静息"直接换算的。模拟器打脸：
一趟完整逃生的实际氧耗约 560–620，于是**玩家平均揣着 38% 的氧气死掉**，
低氧时间只有 3.1%，而那 46% 的"窒息"其实全是 CO2 中毒。
氧气条既然从不见底，支柱 P2"氧气即货币"就只是一句标语。

680 让典型结局落在 11%–16% 余氧，低氧时间升到 15%–20%：
够走完，但最后一层必须开始算账。

这条修正是靠**把"窒息"拆成"氧尽"和"CO2 中毒"两栏**才发现的——
契约把它们并成同一个 `DeathCause`，而调参时它们的处方完全相反。
模拟器现在单独报告 CO2 死亡占比。

### 6.2 加入过度换气，屏息流 7.5% → 39.3%

见 §1.4。核心洞察是：屏息在氧气上是净亏的，所以它必须换来别的东西
（安静、可下水、压迫感减半），并且必须有一个主动"还债"的动作。
缺了任何一半，屏息潜行都不是一条可行路线，而是一个惩罚玩家读了设计文档的陷阱。

### 6.3 修正喘息相的积分 bug，喘息室 1.0 → 1.5–1.8

见 §4.1。这是一个因子错误吃掉了整个节奏系统的典型案例：
`reliefDrain`（0.012）和强度积分速度（约 0.0126）差了 5%，
方向相反，于是导演进得去出不来。
节奏曲线的每一个因子都是"有或没有"的问题，不是"大一点小一点"。

### 6.4 低温从"天气"改成"地点"

初版把淹水做成了全局环境量，结果 69% 的死亡是低温，游戏变成体温管理模拟器。
改法有两条：
其一，水位过一个指数曲线（`floodExponent`）再参与散热——
只有真正浸到身体的水才带走热量，脚踝深的积水不该和没顶一样致命。
其二，涉水区成段出现（水位 0.55–0.82），
因为低温必须靠"一段路"而不是"一个房间"才能致死。
最终低温稳定在 4.7%。

### 6.5 外伤必须有一条不依赖聆听者的来源

把聆听者的即死率调低之后，外伤死因直接归零——
因为它此前完全是"被抓住但没死"的副产品。
现在有四条独立来源：撬门、黑暗/淹水中奔跑、把手伸进黑暗的机械里搜刮、从缠住的线缆里挣脱。
后两条同时削掉了搜刮流的统治性（57% → 37%），一箭双雕。

### 6.6 溺毙要惩罚"计划外"而不是"算错了"

过度换气进来之后，溺毙掉到 0.9%——因为纪律好的玩家再也不会带着高 CO2 下水。
但水不该只惩罚算术错误。加入**缠绕**（11% 概率，横渡时长变成 2.1 倍）之后，
真正让水危险的是它会超出计划：一次算好的横渡突然变成两倍长。
溺毙回到 12.2%。

### 6.7 SAN 流失系数整体下调约 35%

初版四种原型的 SAN 中位数全部低于 15，玩家在第二层就见底了。
SAN 归零不死（GDD §4.2），但它是 Veracity Layer 的输入——
过早见底意味着 L4/L5 的内容在第二层就全部放完，后面三层无牌可打。
现在中位数落在 26–63，污染度 0.35–0.61，
玩家在正常一局里会经历 L2→L4 的完整爬升。

## 7. CONTRACT CHANGE REQUEST

以下三点是 `src/core/contract.ts` 的实际约束，均已用本地方案绕过，不阻塞开发。
列出来是给下一次契约修订做输入。

### 7.1 `SimEvent` 缺少噪音事件

强制大喘气必须向当前房间注入 25 点噪音（GDD §4.3 噪音源表明文），
但 `advance()` 只返回 `SimEvent[]`，而 `SimEvent` 联合类型里没有"噪音"这一项。

**现方案**：`VitalsEngine` 内部累积 `pendingNoise`，主循环用 `takeNoise()` 取走。
可用，但它是一条不在类型系统里的侧信道——调用方忘记调用 `takeNoise()`
不会有任何编译期或运行期提示，噪音会静默丢失。

**建议**：`SimEvent` 增加 `{ kind: 'noise'; roomId: ID; amount: number }`。

### 7.2 `DerivedStat` 缺少 `gaugeTrust`

`fx.hyperventilation`、`fx.hidden.gauge-lie` 这类"影响玩家对仪表信任度"的效果
目前只能挂到 `lucidity` 上。语义是相近的但不等价：
`lucidity` 是"识破谎言的能力"，而仪表可信度是"读数本身的偏差幅度"，
前者是主动的，后者是被动的。合并之后，一个提升 lucidity 的道具
会顺带修好玩家的氧气表，这在叙事上说不通。

**建议**：`DerivedStat` 增加 `'gaugeTrust'`。

### 7.3 `DeathCause` 的 `asphyxiation` 混合了两种死法

氧尽（缺氧）和 CO2 中毒（高碳酸血症）共用一个 `DeathCause`。
它们在生理上确实都叫窒息，但在**调参**上是两回事：
前者说明氧气经济偏紧，后者说明屏息/通风的循环有问题，处方完全相反。
§6.1 那条最重要的修正就是被这个合并掩盖了十几轮。

**现方案**：模拟器在死亡时检查 `oxygen > 0` 来区分，单独统计。
**建议**：拆成 `'hypoxia'` 与 `'hypercapnia'`，或增加一个 `DeathDetail` 字段。

## 8. 距离 3A 丰富度还差什么（诚实评估）

按优先级：

1. **状态效果之间几乎没有交互规则**。66 个效果各自独立生效，
   但真正有质感的系统应该有组合律：低温 + 失血应该比两者相加更糟；
   镇静剂应该压制恐慌但同时压制过度警觉；肾上腺素不该能和镇静剂共存。
   现在这些都只能靠数值巧合。需要一张显式的 `interactions` 表。

2. **Veracity 的文本污染语料量不足**。形近字表约 40 组、近义错义表约 30 组、
   闯入句约 20 句。一局下来玩家会看到重复的变异，
   而重复是"识破"最廉价的途径——它让招牌机制自己拆自己的台。
   这部分需要的是内容量而不是代码：目标至少 200 组形近字、150 组词替换、120 句闯入句。

3. **导演的行为画像只影响伪造偏置和怪物池**，没有影响世界生成。
   Alien: Isolation 的双 AI 之所以成立，是因为导演能影响**空间**。
   现在导演不能要求世界生成器"在他前面放一个死胡同"，
   因为那是 `src/world` 的职责，而我们之间只有 `DirectorOrder` 这一条窄接口。
   需要扩充 order 的种类。

4. **没有单元测试**。序列化往返、阈值穿越、派生属性的 add/mul 顺序
   这三处都是"错了不会崩、只会数值悄悄不对"的地方，最需要测试保护。
   目前的验证完全依赖平衡模拟器的端到端行为，它能发现系统性偏差，
   但发现不了边界条件。

5. **平衡模拟器的玩家模型是策略原型而非学习型 agent**。
   现在的四个原型是固定权重的，它们不会"学会"利用某个 exploit。
   真实玩家会。要发现统治性策略，最终需要让 agent 自己搜索策略空间。

6. **感染五期的正收益期还不够诱人**。设计意图是让玩家**主动**想走到第四期，
   然后发现自己下不来。但目前第四期的收益（breathCost ×0.88）
   在模拟器里不足以改变任何一个原型的行为——没有一个原型会为了它去冒险。
   这个"浮士德交易"目前只存在于文档里，不存在于玩家的决策里。
