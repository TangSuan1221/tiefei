# 主游戏成品关卡接入

主游戏 `/` 通过 `PodExpedition` 在到站时创建当前章节的 `createExpedition` / `createExpeditionWorld`。不再只在独立 `/expedition.html` 使用成品关卡。

- 七关均为原成品的 28 个房间，门、设施、材质、叙事布景复用同一构建器；读取原 CC0 表面贴图，使用 SSAO、水体后处理、悬浮物和局部灯光。
- 舱外摄像机、曝光首帧、驾驶位移、物理门、物品射线使用同一关卡坐标。碰撞使用原成品的通行体积、障碍、物品边界与门禁，按不大于 8cm 的步长检测。
- F 或水平操作台的「操作 / 取回」使用 3.4m 射线，第一可见实体遮挡后方交互。阶段授权与物品由原 expedition 状态机负责，任务道具记录在该设施状态，而非旧打捞库存。
- 领航台在设施内显示成品地图。完成设施出口交互且分析本关录像后才能离站；第七关仍需无线电结局选择。旧生成器仍为无视图的历史测试及部分后台分析提供兼容数据，不再驱动浏览器中的场景移动、实体门或离站判定。
- 不把独立 expedition 页面的存档直接套入主游戏，避免地图进度和主剧情错配。主游戏全流程存档仍未在本次实现。

## 驾驶位

水平操作台采用固定近距离坐姿。窗口距离约 1.10m，不因操作台取景而后退。右键上下拖动俯仰视线，低头使用仪器；左键拖动摇杆。8px 中央死区、110px 操作行程；松手/失焦/指针取消自动回中。转舵响应上限由约 6.9°/s 调整到 15°/s，保留惯性。

## 验证与边界

- 71 项剧情、驾驶、关卡内容及空间结构回归通过。
- 浏览器逐关创建七个主游戏成品世界，检查入口截图、不同朝向关键帧、近距离记录交互、拒绝远距取物、关闭门碰撞、开启门和录像离站门槛。
- 浏览器实际鼠标测试近距离平视/低头不后移、操作台照明键与摇杆推进。
- 构建通过。测试使用受控起点，不代表七关连续真人通关，也尚未完成全流程资源消耗和平衡验收。碰撞沿用成品探索运行时的 0.28m 操作半径，不是整艘潜艇的刚体外形模拟。
