# 《铁肺迷城 IRONLUNG MAZE》美术圣经

> 表现层（渲染 / 程序化音频 / UI）的唯一事实来源。
> 本文件与 `src/render/palette.ts`、`src/render/post.ts` 的 `POST_CHANNELS`、
> `src/audio/cues.ts` 的 `CUE_META` **保持机械同步** —— 改代码就要改这里，反之亦然。

---

## 0. 一句话

**玩家看不见潜艇。玩家只看得见一块声呐屏、一圈仪表，和面罩内壁上自己的倒影。**
所有美术决策都服从这一条：我们不是在渲染一艘船，我们是在渲染一个人被困在铁壳里的视野。

## 1. 调色板

四色主调锁死（GDD §8.1），任何新元素都必须落在这四色或它们的派生色上。

| 角色 | 名称 | HEX | 用途 |
|---|---|---|---|
| 主色 | 铁锈橙 `rust` | `#c4632a` | 舱壁、管道、仪表刻度、声呐磷光。**画面里 90% 的「颜色」都是它。** |
| 底色 | 深渊蓝黑 `abyss` | `#060a10` | 背景、阴影、面板底、所有"没有光的地方"。 |
| 前景 | 骨白 `bone` | `#d8d2c4` | 文字、指针、高光、关键读数。**永远是画面最亮的东西。** |
| 警示 | 警示血红 `blood` | `#8e1620` | 应急灯、红区、不可逆选项、Veracity 撒谎时的漏光。**吝啬使用 —— 它一出现就必须意味着代价。** |

派生色见 `src/render/palette.ts`（`rustDeep` / `rustHot` / `ember` / `boneDim` /
`boneWhisper` / `bloodHot` / `bloodDim` / `phosphor*`）。

### 1.1 绝对禁令

**禁止"恐怖游戏绿"**（`#00ff41` 一族：色相 90°–160° 且饱和度 > 0.35 的任何颜色）。
这不是品味问题，是识别度问题 —— 一旦出现绿色示波器，本作就变成了另外三百个游戏。

`palette.ts` 里有 `isHorrorGreen()` 与 `assertNoHorrorGreen()`，演示页启动时会
遍历整个调色板做断言，控制台报错即视为构建失败。

### 1.2 亮度预算

| 层 | 允许的亮度上限 | 理由 |
|---|---|---|
| 舱壁 / 管道 / 锈迹 | 0.42 | 它是"环境"，不是"内容"。超过这个值就会跟声呐屏抢注意力。 |
| 仪表盘面 / 示意图 | 0.55 | 可读即可。 |
| 声呐屏内容 | 0.85 | 画面唯一允许接近过曝的区域。 |
| HUD 线条与文字 | 0.95 | 骨白，最亮。 |
| 应急灯核心 | 1.0 | 但半径必须 < 画面高度的 0.20 —— 见 §2.3。 |

## 2. 构图原则

### 2.1 视线漏斗

画面从外到内一共三道收束，**每一道都必须比上一道亮**：

```
深渊蓝黑（边缘，晕影压到 15%）
  └─ 舱内剖面（铁锈橙，中等亮度，提供纵深与"我在哪"）
       └─ 声呐屏（唯一的亮区，玩家 80% 的注视时间在这里）
            └─ 光点 / 回波（画面最亮的像素）
```

违反这条的典型事故：把应急灯开得又大又亮，左上角烧出一团橙雾，玩家的眼睛
就被拽到了一个没有信息的角落。**在项目早期真实发生过一次，修法记录在 §2.3。**

### 2.2 版面分区（按画面高度 h 归一）

| 区域 | 位置 | 内容 |
|---|---|---|
| 左上 | `0.118w, 0.105h` | 理智示波器（SAN 走线） |
| 左中 | `0.115w, 0.44h` | 状态图标 + 事件日志 |
| 左下 | `0.118w, 0.78h` | 氧气压力表 |
| 正中 | `0.37w, 0.44h` | **声呐屏**（视觉主体） |
| 右上 | `0.90w, 0.105h` | 深度数码管 + 压力条 |
| 右中 | `0.78w, 0.40h` | 舱段剖面示意图 + 四联仪表 |
| 右下 | `0.885w, 0.845h` | 噪音表（VU + 峰值保持） |
| 底中 | `0.5w, 0.905h` | 呼吸弧 + 屏息计时 |
| 底缘 | `0.5w, 0.96h` | 生理值细条 |

左重右轻、上紧下松。底部 1/5 是控制台金属，**必须被非对称晕影压住**，
否则那一大片浅色会持续把视线往下拖。

### 2.3 光源纪律

程序化光照最容易翻车的地方就是"光源半径给太大"。铁律：

* **应急灯**：半径 ≤ `0.46h`，强度 ≤ 0.40。它是一盏 20 W 的灯，照不亮一个舱。
* **第二盏冷光**：半径 ≤ `0.40h`，强度 ≤ 0.20。
* **声呐屏辉光**：半径 ≤ `1.75 × 屏半径`，强度 ≤ 0.42。**唯一允许照亮一片区域的光源**，因为玩家本来就要看它。
* **手电**：半径 ≤ `0.82h`，强度 ≤ 0.66，位置随呼吸相位上下 `±0.012h`。

衰减曲线固定为 `1 → 0.45 @35% → 0.12 @72% → 0 @100%`（近似平方反比）。
光照全部画在一张 1/4 分辨率的 lightmap 上再 `multiply` 回场景，
所以加光源几乎不要钱 —— **但不要因为便宜就加**。

### 2.4 程序化细节密度

每个元素都要有三层：**形状 → 材质噪声 → 损伤**。
只有形状的管道看起来像 flash 动画；加了锈迹与渍水痕之后才像在水下泡了四十年。

* 锈迹：`fbm2` 四阶，`overlay` 混合，只落在铆钉与焊缝附近（用距离场加权）
* 渍水痕：竖向拉长的 `valueNoise2`，从管道接口向下流
* 铆钉：每根钢梁 8–14 颗，位置由 `hash2(梁序号, 颗序号)` 决定，带各自的高光角

所有噪声来自 `src/core/rng.ts`，**全流程零 `Math.random()`** —— roguelite 的
同种子回放必须逐像素一致。

WebGL2，7 个 shader program，13 次 draw call，5 级泛光链。

| # | 通道 | Pass | 驱动参数 | 做法 |
|---|---|---|---|---|
| 1 | 桶形畸变 | `warp` | `barrel` | 径向 r²/r⁴ 双项，模拟球面舷窗玻璃 |
| 2 | **呼吸起伏** | `warp`+`grade` | `breathe` | ±0.6% 缩放 + 竖向微位移 + 亮度呼吸，**吸气比呼气快（1.35 : 0.85）** |
| 3 | SAN 几何扭曲 | `warp` | `warp` | fbm 域扭曲 + 同心膜波 + 高污染时的行错位撕裂 |
| 4 | 焦散折射 | `warp` | `caustics` | 用焦散场的屏幕梯度推采样点 —— 隔着水看东西 |
| 5 | 色差 | `warp` | `aberration` | 径向 RGB 三次采样，中心零、边缘最大，**上限 4 px** |
| 6 | 亮度提取 | `bright` | `bloom` | 软拐点阈值 0.80 / knee 0.22 + Karis 均值抑制萤火虫 |
| 7 | **多级泛光** | `down`/`up` | `bloom` | 5 级 13-tap 降采样 + 9-tap 帐篷上采样，**逐级 0.62 衰减回填** |
| 8 | 焦散光斑 | `grade` | `caustics` | 4 次折返迭代，只染铁锈橙，且只落在暗部 |
| 9 | 色调分级 | `grade` | `tint` | ACES + 阴影压深渊蓝 / 中调轻推铁锈 / 高光提骨白 |
| 10 | 曝光 | `grade` | `exposure` | 心跳与应急灯闪烁都在推它 |

| 13 | 扫描线 | `film` | `scanline` | 行间隙 + RGB 孔径栅格 + 缓慢滚动的回扫亮带 |

### 3.1 调参血泪（不要重蹈覆辙）

这四条是第一版翻车之后总结的，**每一条都对应一张很丑的截图**：

1. **泛光必须逐级衰减。** 5 级无权重相加 = 能量 ×5，整屏糊成一片发光的橙雾，
   深渊蓝黑彻底消失。回填权重 0.62、合成权重 0.30、阈值 0.80 —— 让**光源**发光，
   不要让**锈墙**发光。
2. **ACES 之后必须补对比与黑位。** 色调映射会把中间调抬"奶"，
   `mix(col, smoothstep, 0.42)` + 减 0.02 黑位归一，这五行是"像不像 3A"的分水岭。
3. **掉线带不是黑杠。** `mix` 权重不夹住就会出现几条贯穿全屏的纯黑横条，一眼假。
   掉线是"信号变弱"（去饱和 + 轻微偏蓝），不是"画面变黑"，且权重上限 0.62。
4. **隧道视野必须是屏幕空间正圆。** 用 uv 空间半径会得到一个宽扁椭圆，
   读起来只是"画面变暗了"，而不是"我的视野在合上"。

### 3.2 呼吸起伏为什么最重要

GDD §8.1 点名它是性价比最高的沉浸感来源，实测确实如此：
它是**唯一一个玩家不会有意识注意到、但关掉之后立刻觉得"死了"**的通道。

* 相位来自 `src/audio/breath.ts` 的 `BreathClock`，**与音频共用同一个相位值** ——
  画面起伏和呼吸声必须严格同相，差 100 ms 就会产生说不出的别扭。
* 吸气快呼气慢（1.35 : 0.85）。人在紧张时就是这样呼吸的。
* 屏息时相位冻结、画面停止起伏、全局低通落下 —— **世界被闷住**。

## 4. 声呐屏规范

玩家看它的时间超过看别的一切的总和，它的质感决定了整个游戏的质感。

| 元素 | 规则 |
|---|---|
| 磷光衰减 | 独立的 persistence buffer，每帧乘 `0.92 ~ 0.965`（随 SAN 变化），**不是 alpha 叠加** |
| 扫描点亮 | 目标只在扫描线**扫过的那一刻**被点亮，之后靠磷光缓慢褪去 |
| 回波强度 | 亮度 ∝ 目标反射面积 / 距离²，远处的大物体和近处的小物体应该一样亮 |
| 距离环 | 4 环，实线，标数字；**烘焙成静态图层**，不逐帧重画 |
| 方位刻度 | 每 30° 主刻度带三位数字（000/030/…），每 10° 副刻度 |
| 噪点干扰 | 底噪密度 ∝ 深度 + 污染度；低 SAN 时出现**对不上的回波** |
| 波前 | 全功率脉冲时从中心向外爬一圈可见波前，2.4 s 内到达边缘 |
| 玻璃 | 表盘玻璃的划痕与气泡烘焙成静态图层，永远固定 —— 它是一块真玻璃 |

## 5. 音频 cue 清单

**全程程序化 WebAudio 合成，零外部音频素材。**
GDD §9 要求 ≥ 40 个 cue（最低 25），**实装 85 个**（`CUE_COUNT`）。

### 5.1 常驻合成层（不在 cue 表里，由 `AudioEngine` 持续驱动）

| 层 | 合成方式 |
|---|---|
| **心跳** | 两个带包络的低频正弦（48 Hz / 72 Hz）+ 噪声瞬态；BPM = `58 + fear × 0.78`，S1/S2 双音间隔随 BPM 收缩 |
| **呼吸** | 滤波白噪声 + 三个共振峰；**吸气锐、呼气钝且更长**，与 `BreathClock` 同相 |
| **船体应力** | 低频金属共鸣簇；**深度越深基频越低、事件越密**（`38 Hz → 22 Hz`，间隔 34 s → 9 s） |
| **耳鸣** | 4–8 kHz 纯音，低 SAN 时淡入，带 ±6 cent 的缓慢滑音 |
| **环境音床** | 6 张：`hull` / `machinery` / `flooded` / `chapel` / `void` / `bridge`，交叉淡入淡出 |

### 5.2 声呐的空间感

`sonarPing(power, echoes)` 是**唯一真正制造空间感的东西**：
啾啾脉冲（1200→600 Hz 扫频）之后，按每个房间的实际距离计算多抽头延迟回波，
延迟 = `距离 × 2 / 1500 m·s⁻¹`，增益按距离衰减，声像按方位。
玩家闭上眼睛也应该能大致说出哪个方向有东西。

### 5.3 动态混音

| 触发 | 效果 |
|---|---|
| **屏息** | 全局低通 `18 kHz → 420 Hz`（0.35 s 过渡）+ 心跳总线 +6 dB + 呼吸总线静音 |
| 低 SAN | 耳鸣淡入、混响尾加长、`san.*` 随机点缀出现频率上升 |
| 深度增加 | 船体应力变频变密、底噪次声层加重 |
| 进水 | `flooded` 音床、高频整体衰减 |

## 6. UI 规范

### 6.1 第一原则：HUD 不是浮层

HUD 是**投在面罩内侧那层曲面玻璃上的光**。所以它：

* 画在**独立的 canvas** 上，由 `post.ts` 用**比场景更强的曲率**（`barrel × 2.1 + 0.12`）去弯
* 单独吃色差、划痕、反光扫掠与呼气起雾
* 随呼吸相位相对眼睛微动
* **所有元素都是发光的细线，没有实心色块** —— 投影没有不透明的东西

### 6.2 可读性的全部秘密

**不要把字画得更亮，要把字背后的东西压暗。**

`HudRenderer.drawScrim()` 在每个读数簇后面画一块椭圆"熏黑玻璃"
（真实的潜水面罩与飞行头盔都这么做），合成时 `col × (1 − hudA × 0.80)`。
第一版没有这一层，结果所有小号中文都被背后的锈墙吃干净了。

### 6.3 氧气是压力表，不是数字条

指针用**弹簧–阻尼**跟随目标（k=26, c=7.2），叠加两层手抖：
高频 `±(0.004 + fear × 0.016)` + 低频 `±0.006`。**你的手在抖，所以指针在抖。**
数码管给精确值、指针给体感值 —— 这也是 §6.4 撒谎的前提。

### 6.4 低 SAN 时 HUD 自己撒谎

**没有任何提示。** 四种撒法轮换，每次持续几秒：

| 撒法 | 表现 |
|---|---|
| `needle` | 指针指向一个不存在的读数，但数码管是对的 |
| `number` | 数码管漂移，但指针是对的 |
| `label` | 标签被换成"差不多对"的词（氧气→储气、深度→压强、理智→共鸣） |
| `ghost` | 多出一行几乎看不见的、不同的读数 |

触发概率 ∝ corruption。玩家只能靠**交叉验证指针与数码管**自己发现不对 ——
这正是 Veracity Layer 想要的猜疑。

### 6.5 中文排版

* 正文用无衬线 CJK，标题用等宽/工业风，数字一律等宽
* **标点不能出现在行首**（`。，、；：？！》」）`）**也不能出现在行尾**（`《「（`）
* 中西文之间自动插入 1/4 em 空隙
* 按**像素宽度**折行，不是按字数 —— 中英混排按字数折必然参差
* 字距：标题 `+0.004h`，正文 0，数码管 `+0.09` skew
* 层次靠**亮度**而不是字号：主读数骨白 0.95 / 次级 0.62 / 说明 0.40

实现在 `src/ui/typography.ts` 的 `layoutCJK()`。

### 6.6 四个面板

`dialogue` / `inventory` / `map` / `log` 共用同一套"投影板"语言：

* 开合是**竖向展开**（`smoothstep(open)` 驱动高度），不是淡入
* 底板 `rgba(6,10,16,0.90~0.94)` + 一层极淡的暖色径向，避免面板"死"
* 上下双主线（铁锈橙 0.72）+ 四角括号（余烬色 0.65）
* 面板打开时整个世界压暗 0.70 —— 注意力管理
* 左侧竖向刻度尺、底部按键提示，两者贯穿四个面板保持一致
* 不可逆选项用警示血红 + `ui.confirm-irreversible`

## 7. 性能预算

| 项 | 预算 | 实测 |
|---|---|---|
| 帧率 | 60 FPS | 60.3 FPS（1600×900，rAF 计数 4 s） |
| draw call | ≤ 16 | 13 |
| 中间缓冲 | ≤ 8 | 8（3 全分辨率 + 5 级泛光链） |
| 色深 | HDR 优先 | RGBA16F（`EXT_color_buffer_half_float`），降级 RGBA8 |
| 内部渲染分辨率 | ≤ 2.6 Mpx | 超过按比例缩 |

优化手段：静态图层全部烘焙（声呐刻度环、玻璃缺陷、舱内锈迹底）、
lightmap 走 1/4 分辨率、UV 域的 5 个通道合并进同一个 fragment
（它们本质都是对采样坐标做变换，拆成多个 FBO 只会多付带宽）。
